### ISSUE-01：剧情站企划和组合旁的数量显示过小

- 状态：**仍存在**
- 建议优先级：P2
- 涉及区域：剧情档案企划栏、组合筛选栏、组合标题

#### 原始反馈

剧情站中用于表示偶像或内容页数量的数字太小，可以考虑直接去掉，避免产生视觉干扰。

#### 当前现状

新版剧情档案仍在多个位置展示数量：

- 企划标签展示 `entryCount` 或 `idolCount`。
- 组合筛选按钮展示当前组合的内容页数量。
- 组合标题右侧展示内容页数量。
- 这些数字主要使用 `text-xs text-muted-foreground`，视觉层级较弱。

#### 代码证据

- `apps/web/app/pages/wiki/modern/wiki-index-page.tsx:220`
- `apps/web/app/pages/wiki/modern/components/wiki-group-filter.tsx:138`
- `apps/web/app/pages/wiki/modern/components/wiki-idol-grid.tsx:97`

#### 建议方案

先确认数量是否具有实际决策价值：

- 如果没有明显价值，移除企划和筛选按钮中的数量，只在分组标题保留汇总。
- 如果需要保留，增加最小字号和对比度，并避免数字紧贴长名称。
- 移动端可隐藏次要数量，桌面端保留。

#### 验收标准

- 企划和组合名称在窄屏下不因数量挤压而截断或难以识别。
- 数量信息不会比名称更抢眼，也不会小到难以阅读。
- 桌面与移动端均通过视觉检查。

### ISSUE-02：移动端分类名称过长且术语不直观

- 状态：**仍存在**
- 建议优先级：P1
- 涉及区域：闪耀色彩剧情分类、移动端剧情筛选

#### 原始反馈

部分手机无法完整显示分类名称。建议把 `enza组合` 等名称替换为更容易理解的名称，例如“游戏组合”“手游组合”。

#### 当前现状

当前实现仍直接使用历史分类名称和数据库名称，没有针对移动端提供短名称或用户友好的展示名称。源码中仍存在：

- `enza组合剧情`
- `scsp活动`
- `enzaP卡`
- `enzaS卡`

分类布局虽支持响应式网格，但没有术语映射或短标签机制。

#### 代码证据

- `apps/web/app/pages/wiki/wiki-model.ts:13`
- `apps/web/app/pages/wiki/wiki-model.ts:33`
- `apps/api/src/infra/db/sqlite/schema-strategy.ts:543`

#### 建议方案

- 保留稳定的内部分类代码，在 API 或前端模型中增加 `displayName` 和可选的 `shortName`。
- 避免直接修改数据库主键或依赖名称进行关联。
- 在移动端使用短名称，详情标题或提示中保留完整名称。
- 与内容维护者确认最终术语，例如“网页游戏组合剧情”“手游组合剧情”。

#### 验收标准

- 320px 宽度下分类标签完整可辨认。
- 用户无需了解 `enza`、`SCSP` 缩写也能理解分类。
- 分类重命名不破坏已有剧情数据和后台管理关联。

### ISSUE-03：企划介绍页“剧情浏览”无法进入对应内容

- 状态：**仍存在**
- 建议优先级：P0
- 涉及区域：作品/企划介绍页、剧情详情路由

#### 原始反馈

各企划介绍页面中的“剧情浏览”无法正确跳转到对应剧情。

#### 当前现状

各企划介绍页的“剧情浏览”链接统一指向 `/story`，没有携带企划或偶像参数。剧情页在缺少这些参数时只会显示“请选择一个内容页”和“剧情地址缺少企划或内容页信息”。

因此链接本身可以打开，但无法到达对应企划的有效剧情目录。

#### 代码证据

- `apps/web/app/pages/works/works-content.ts:54`
- `apps/web/app/pages/works/works-content.ts:83`
- `apps/web/app/pages/works/works-content.ts:112`
- `apps/web/app/pages/wiki/modern/story-page.tsx:176`

#### 建议方案

企划级入口不应直接进入需要“企划 + 内容页”参数的剧情详情页。可选择：

1. 跳转到对应企划的目录：`/wiki/modern?agency=<企划名称>`；或
2. 为 `/story` 增加真正的企划级入口页面。

方案 1 改动更小，也与当前剧情档案的信息架构一致。

#### 验收标准

- 从任一企划介绍页点击“剧情浏览”后，能直接看到该企划的内容目录。
- 不再出现“剧情地址缺少企划或内容页信息”。
- 返回、经典视图和新版视图之间的参数保持一致。

### ISSUE-08：没有 SDM 内容的偶像仍可能出现剧情跳转

- 状态：**需要运行时数据确认**
- 建议优先级：P1
- 涉及区域：剧情档案内容页卡片、公开 Wiki API

#### 原始反馈

没有 SDM 内容的偶像不应显示跳转入口。

#### 当前现状

当前前端源码中已经没有 `sdm` 专用入口或硬编码标记。但是公开 Wiki API 返回的每一个内容页都会被无条件渲染为剧情详情链接，没有检查该内容页是否实际存在剧情分类或可用来源。

因此：

- 如果生产数据已移除空 SDM 内容页，问题不会出现。
- 如果生产数据仍返回空内容页，前端仍会生成可点击入口。

#### 代码证据

- `apps/web/app/pages/wiki/modern/components/wiki-idol-grid.tsx:103`
- `apps/web/app/pages/wiki/modern/components/wiki-idol-grid.tsx:106`

#### 建议方案

- 在公开目录 API 中返回 `storyCount` 或 `hasPublishedStories`。
- 对没有内容的条目禁用跳转，或从公开目录中过滤。
- 对生产数据库执行一次空内容页查询，重点确认历史 SDM 记录。

#### 验收标准

- 没有已发布剧情的内容页不会进入空剧情页面。
- 后台仍能管理未发布内容，不因公开过滤而丢失数据。
- 使用生产数据或等价快照完成验证。

#### 原始反馈

生日名单希望增加偶像头像，点击后可以跳转到偶像个人页面。个人页尚未完善时，可以先保留跳转能力的设计。

#### 当前现状

当前生日记录只有：

- 姓名
- 生日
- 代表色
- 所属企划
- 派生出的月份和日期

生日名单只渲染代表色圆点、姓名和企划，没有头像、内容页 ID 或跳转链接。

#### 代码证据

- `apps/web/app/pages/home/birthday-data.ts:4`
- `apps/web/app/pages/home/components/birthday-calendar.tsx:244`

#### 建议方案

- 不在生日 JSON 中重复维护头像 URL。
- 使用“企划代码 + 偶像稳定 ID”关联 Wiki 目录数据。
- 从 Wiki API 获取头像和公开页面状态。
- 有公开内容页时显示可点击头像和姓名；没有内容页时保留普通文本。

#### 验收标准

- 有 Wiki 内容页的偶像显示头像并可正确跳转。
- 没有内容页的偶像不会产生死链。
- 同名偶像通过稳定 ID 和企划区分。
- 图片加载失败时有不会破坏布局的降级显示。
