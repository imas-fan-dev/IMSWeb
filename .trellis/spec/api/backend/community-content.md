# Community landing configuration

## 1. Scope and trigger

Use this spec when changing `/community`, `/admin/community`, community landing
configuration, or its image upload/delivery. The feature spans contracts, API,
object storage and Web. Authoritative implementation lives in
`apps/api/src/domains/content/community-content/`,
`packages/contracts/src/community-content.ts` and the corresponding Web pages.

## 2. Signatures

`registerCommunityContentRoutes` registers these builder-based endpoints:

| Method | Builder | Purpose |
| --- | --- | --- |
| GET | `communityApiPath('/content')` | Public enabled entries |
| GET | `adminApiPath('/community-content')` | Complete configuration and revision |
| PUT | `adminApiPath('/community-content')` | Save a revisioned draft |
| POST | `adminApiPath('/community-content/images')` | Normalize an uploaded icon image |

Storage operations remain behind `ObjectStorage`:

```typescript
readCommunityContent(storage: ObjectStorage): Promise<CommunityContentSnapshot>
saveCommunityContent(
    storage: ObjectStorage,
    value: CommunityContentDraft,
    expectedRevision: string | null,
): Promise<SavedCommunityContentSnapshot>
```

The configuration uses `COMMUNITY_CONTENT_OBJECT_KEY`; images use
`communityContentAssetObjectKey`. The delivery domain owns public GET/HEAD
through the existing public-upload handler. Do not expose the configuration
object through an anonymous storage URL.

## 3. Contracts

Import schemas/types from `@imsweb/contracts/community-content`. That source
owns entry/draft/content shapes, strict update requests and exact responses;
do not maintain another schema in API domain code. The update route runs
`adminCommunityContentUpdateRequestSchema` at its request boundary. Stored
JSON is validated locally by `parseCommunityContent` without loading Zod.

- Missing configuration returns default page copy, `entries: []`,
  `updatedAt: null` and an admin `revision: null`. It never seeds old cards.
- Explicitly saved empty entries remain empty on reread. Public reads remove
  disabled entries; the Web page filters audience and exchange availability.
- Every entry has a stable unique ID. Array order determines display order.
- `imageUrl` in a draft is null or a canonical upload reference generated by
  this feature. Saving verifies its corresponding object exists. Public reads
  resolve media delivery URLs; Web/App use `resolveSafeMediaUrl`.
- `communityContentEditors` allows op and editor. Cookie writes use
  `backofficeCsrf`; save/upload call the existing best-effort audit writer.
- Saves require `putIfUnchanged`. An adapter without it cannot silently fall
  back to unconditional writes. Configuration bytes are protected in storage.
- Successful uploads remain available to unsaved and concurrent drafts.
  Failed writes use existing deletion/compensation. Clearing a draft reference
  does not delete a successful upload.

### Admin list and candidate Dialog

`apps/web/app/pages/admin/community/` owns the compact list and pinned entry
Dialog. The page holds the loaded baseline, draft and revision; dirty state
compares the draft with the baseline. Opening an editor creates a copied
candidate and records the original ID. Cancel, Escape and outside dismissal
discard the candidate. Confirm validates the existing entry schema through the
Web API facade, checks ID uniqueness and original-target existence, and updates
only that row. An unchanged confirmation leaves the page clean. Adding a row
does not append it before confirmation. Only the page's save action calls the
configuration PUT; candidate confirmation, ordering and deletion stay local.

The editor owns upload state separately from page loading/saving. A response,
catch or finally may change the editor only while its session token, upload
sequence and active flag match. Pending upload blocks closing and confirmation;
unmount invalidates the session. A successful upload is only a candidate image
reference until entry confirmation and page save. Cancelling never deletes the
server asset.

Editing, sorting and deletion locate entries by ID. After an editable ID changes,
closing the Dialog restores focus to the new row's visible edit button; if the
target no longer exists, focus falls back to the add button. Scheduled focus
restoration is cancelled on unmount or opening another session.

The desktop table exposes ordering, edit and delete buttons. Narrow layouts merge
metadata into the entry column and use a local `@base-ui/react/menu` Portal for
ordering/deletion, with 44px targets. The Dialog uses the shared pinned layout,
the complete flex/min-height chain and `DialogBody` as its only scroll region.
Keep the footer and close control reachable, including validation errors.

## 4. Validation and error matrix

| Condition | Result |
| --- | --- |
| Missing configuration | Successful empty entries |
| Malformed or unknown stored fields, invalid UTF-8/timestamp | Infrastructure failure; no empty success |
| Invalid request fields, duplicate IDs, unsafe link | 400; no configuration write |
| Image reference outside this feature or missing object | 400; no configuration write |
| Anonymous admin request | 401 before configuration access |
| Department other than op/editor, or invalid Cookie CSRF | 403 before mutation |
| Stale revision or atomic compare-and-set loser | 409; winner preserved |
| No atomic storage capability | 500; unconditional put is not called |
| Invalid uploaded image | 400; no successful media object |
| Upload exceeds the 10 MB cap | 413 |
| Upload storage failure | Failure with cleanup/compensation |
| Public read fails | Web shows retry; it does not inject cards |
| Admin read/save fails or conflicts | Draft retained, unsafe saving disabled |

Links permit safe single-slash site paths and credential-free HTTP(S). The
local validator rejects protocol-relative paths, dangerous schemes, backslashes
and encoded control characters. Image format, MIME, decoding and pixel limits
use the shared image normalization pipeline.

## 5. Good, base and bad cases

- Good: upload an icon, save its canonical reference with the loaded revision,
  then public read returns the configured entry and its resolved image URL.
- Base: the editor deletes every entry and saves. Both public Web and App
  render an empty entry region under the configured page heading.
- Bad: a read fails, the editor treats it as a new empty configuration and
  allows saving; or a hardcoded exchange card appears despite empty entries.

## 7. Incorrect and correct patterns

Incorrect:

```typescript
const entries = loaded.entries.length ? loaded.entries : oldStaticEntries;
await storage.put(key, body); // Drops the editor's revision protection.
```

Correct:

```typescript
const entries = loaded.entries; // Empty remains a valid configured result.
const saved = await storage.putIfUnchanged(key, expectedRevision, body, options);
if (!saved) throw Object.assign(new Error('Configuration conflict'), { status: 409 });
```

Check atomic capability before writing, and distinguish unavailable storage
from a missing configuration object.
