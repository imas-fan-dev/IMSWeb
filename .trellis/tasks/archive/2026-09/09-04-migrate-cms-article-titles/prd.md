# 迁移 CMS 文章标题

## Goal

批量拆分当前 CMS 文章标题字段中以中文方括号开头的复合文本，使标题与正文分别存储和展示，同时保留已有正文并避免修改不符合规则的文章。

## Background

- 旧活动迁入 CMS 时，`events.title` 被写入 `articles.title`，`articles.body_json` 和 `articles.body_html` 初始化为空。
- CMS 正常编辑会同时维护 `articles.title` 与兼容字段 `events.title`，并增加 `articles.revision`。
- 仓库没有统一的迁移来源字段。本任务不按来源筛选，而是处理所有当前标题符合格式的 CMS 文章。
- `body_json` 是正文的 TipTap 权威格式，`body_html` 是由它生成并清洗的 HTML。

## Requirements

- 提供一次性数据回填脚本，扫描所有 CMS 文章，不限制迁移来源、内容类型、编辑状态或正文是否为空。
- 原始标题去除首尾空白后，必须以 `【非空标题】` 开头才触发拆分。
- 取开头第一对 `【` 与 `】` 之间去除边界空白后的非空内容作为新标题，不保留方括号。
- 方括号出现在文本中间、缺少闭合括号或括号内只有空白时，文章保持原样。
- 闭合括号后的内容去除边界空白后作为待迁移正文，其中出现的其他方括号仍属于正文。
- 待迁移正文非空时，将其转换为一个新段落并放在现有正文前面。保留其内部空白和换行，也保留现有正文的内容及顺序。
- 待迁移正文只有空白时，不新增正文段落。
- 正文变更必须生成一致且合法的 `body_json` 与 `body_html`。
- 对存在关联活动记录的文章，同步更新 `events.title`，使其与 `articles.title` 一致。
- 更新文章时增加 `articles.revision` 并刷新 `updated_at`；迁移不伪造后台用户身份。
- 脚本默认 dry-run，只有显式传入 `--apply` 才写入数据库。
- apply 必须基于事务内重新读取并锁定的当前数据执行。任何冲突或写入错误都中止整批操作并回滚。
- 脚本必须可重复运行。成功处理后的标题不再符合触发格式，后续执行不产生新的数据变更。
- 输出权限受限的审计报告，至少区分候选、将更新、已更新、未匹配、冲突与错误。终端输出不得包含正文等生产内容。

## Acceptance Criteria

- [ ] dry-run 列出拟更新记录及拆分后的标题和正文，并且数据库没有变化。
- [ ] apply 更新所有当前标题符合规则的 CMS 文章，不依赖迁移来源、内容类型或编辑状态。
- [ ] 新标题等于开头第一对中文方括号内去除边界空白后的非空内容，且不包含外围 `【`、`】`。
- [ ] 方括号位于文本中间、缺少闭合括号或括号内为空时，文章保持原样。
- [ ] 闭合括号后的文本去除边界空白后成为现有正文之前的新段落，内部换行可在 TipTap 和 HTML 中正确显示，原正文内容及顺序不变。
- [ ] 拆出的剩余文本只有空白时不新增正文段落。
- [ ] `body_json` 通过现有正文校验，`body_html` 由更新后的 `body_json` 生成并清洗。
- [ ] 存在关联活动时，`events.title` 与更新后的 `articles.title` 一致。
- [ ] 不匹配的记录保持原样，并计入报告中的未匹配分类。
- [ ] 写入前发生冲突或任一写入失败时，整批事务回滚，报告记录失败原因，不留下部分更新。
- [ ] 第二次 apply 不产生新的数据变更。
- [ ] 报告文件权限为 `0600`，终端只输出汇总计数和报告路径。
- [ ] 自动化测试覆盖标题拆分边界、空正文、已有正文前置合并、关联活动同步、dry-run、apply、重复执行、非目标记录、冲突和事务回滚。

## Out of Scope

- 修改 PostgreSQL 表结构或已发布的 schema migration。
- 按旧系统迁移来源筛选文章。
- 修改普通 CMS 编辑流程或前端展示逻辑。
- 自动撤销已经提交的迁移；执行前仍需按运维流程备份数据库。
