# 名片移动端浏览体验重设计

## Goal

重新设计制作人名片墙 `/community/cards` 的移动端浏览体验，让用户以更高密度浏览和比较名片，同时看到正反面，需要阅读细节时点开原图，并在返回列表时保留浏览位置。视觉以真实名片图像为主体，兼顾发现效率与设计感。

## Background

- 社区有制作人名片墙和名片交换事务所两个入口。用户选择本轮仅调整前者。入口来源：`apps/web/app/pages/community/index.tsx:16`。
- 改造前，名片墙手机端将正反面并排缩小展示，并裁切非标准比例图片；大图仅支持同一张名片的翻面。来源：`apps/web/app/pages/community/community-cards-page.tsx:205`、`apps/web/app/components/shared/namecard-preview.tsx:46`。
- 交换事务所是地图与名录结合的发现流程，手机名片列表置于 Sheet，拥有独立的筛选和互动需求。
- 初始研究覆盖页面、预览、分页测试、契约、设计规范和图片生成逻辑，证据见 `research/current-browsing.md`。实现已按后续要求修订并通过最新 Web/App 浏览器验收；原生设备交付状态见 `research/device-delivery.md`。
- 用户在查看实现期间补充要求：移动端应更现代，参考小红书的风格；正反面最好一起展示。这取代原方案中列表一次只显示一面、通过分段控件翻面的要求。
- 用户进一步指出「单列的浏览密度太低了」，否定单列双面上下展示的建议，明确要求提高列表密度。随后用户在双列最终摘要后回复「开始，不过最好和xhs一样有一些错位」，批准双列、双面同显，并追加轻微高低错落的视觉要求。

## Requirements

### R1 浏览与视觉

自然上下滚动浏览，不采用整屏强制翻页。每张名片的正面、背面默认一起展示，不需要先切面才能查看另一面；点击任一面打开对应原图。一起展示指两个面都不隐藏，不要求在每一种短屏中把两面强行缩进一屏。

视觉参考小红书移动端图片信息流。按用户截图后的新要求，每个名片对象在视觉上归入一个 Card：正反面、提交时间、emoji 与认领状态共享同一背景、轻边框和圆角，不能像分散的图片与文字块。不嵌套多个 Card，不新增独立灰底操作区或大面积按钮；内容紧凑，保留必要的触控尺寸。使用现有中性色与少量品牌强调色，不新增装饰性首屏。

手机采用顶部对齐的双列卡片流。用户最新要求取消刻意错位：每列根据名片的实际 emoji 数量及其他内容高度独立向下排列，不按行等高，不补齐较短条目的空白，不使用固定像素位移。内容等高时允许自然对齐；内容不等高时产生自然高低差。每张名片内部正面在上、背面在下，两面完整同显。列表供快速发现和比较，较小文字通过点击原图阅读；保留顺序、正常间距、完整内容和触控尺寸，不产生重叠。

图片和文字不因装饰性处理被裁切或遮挡；不虚构昵称、头像、标题、编号展示或统计，不新增没有业务支持的关注、收藏功能。正文、空态和错误反馈保持中文。

### R2 连续预览

大图提供上一张、下一张操作，顺序与列表一致。到达页边界时按需加载相邻页，不要求先关闭预览再手动翻页。第一张和最后一张有清楚的边界状态，不循环回绕。

打开时展示列表中直接点击的那一面；切换到另一张名片时回到正面并复位缩放和位移。保留现有缩放、拖动、复位、键盘翻面、Escape 关闭和静止点击空白关闭能力，不将图片拖动误判为翻面、切卡或关闭。

相邻页请求失败时保留当前名片，允许重试和关闭。快速连续操作、关闭或重新打开预览后，旧请求不能覆盖新状态。

### R3 返回与分页

关闭预览后回到最初打开它的列表位置和触发控件。预览内跨页阅读不改变背后的列表页码、每页数量或双面条目。

列表保留 URL 页码、每页 12/24/48 张、上一页、下一页和指定页跳转。按最新截图反馈，手机分页集中为两行：主行包含上一页、页码/总页数、跳转与下一页，次行包含总量/当前页说明和每页数量，不把控件分散为四段。支持回车跳转、Escape 取消页码草稿；未修改页码时不重复请求，非法输入有明确反馈，完成翻页后新页起始内容可见。保持至少 44px 触控目标，不改成无限滚动。

### R4 业务与状态

保留完整表情反应选择、计数更新与原有限制；保留历史名片认领的登录与状态约束，以及壳层拥有的上传入口。保留列表加载、空态、错误、重试和翻页反馈。

图片加载中或失败时维持条目尺寸，并提供可辨认的状态；缩略图失败后允许尝试原图，原图失败不能反复请求或无限重试。

### R5 兼容与可访问性

Web 和 App 使用同一页面；保留桌面端现有多列、正反并排的浏览结构。大图新增的连续浏览能力在桌面也可使用，原有键盘行为不变。

主要触控目标至少为 44 × 44 CSS 像素。文字、图片、弹层与操作按钮不重叠，不产生意外横向滚动；预览避让四侧安全区，列表不重复计算 App 顶栏和底栏高度。所有操作可通过明确控件完成，不依赖悬停。

### R6 App 避让与信息简化

按最新真机反馈修复分页遮挡：App 悬浮上传和返回顶部在分页进入视口时让位，离开分页后恢复，不以缩小分页控件或固定空白替代修复。保留前后翻页和页大小/跳页功能，并实际检查 App 控件之间的命中位置。

提交时间改为简短日期，例如 `2026-08-20`；完整时间继续保留在语义数据与可访问说明中，缺失或非法日期显示短提示。

名片反应列表与选择器使用随包分发的同一套图形，不使用系统原生 emoji 字形或运行时远程图片。Web、Android、iOS 图形一致，反应种类、Unicode API 值、计数与点击规则不变；包含合法来源和许可说明。

### R7 紧凑反应区

用户在 iOS 模拟器截图中要求缩小名片内的 emoji 交互，每行最多 4 项。缩小列表中的图形、计数字号及留白，加号也计入每行上限；保留至少 44px 触控尺寸。可用宽度不足或计数较长时自然换行，完整保留数值。表情选择器、桌面样式、统一资产和反应规则保持不变。iOS 继续使用模拟器验证并更新 Release，不操作真机。

### R8 分钟级时间

用户要求名片显示时间精确到分钟。列表改为紧凑的 `MM-DD HH:mm`，例如 `08-20 14:35`，继续按北京时间显示；完整年份和秒数保留在时间说明与 ISO 语义数据中。保留无效/缺失提示，不增加相对时间刷新，不修改 API。与 R7 一同验证并更新 iOS 模拟器 Release。

## Out Of Scope

- `/community/exchange` 地图、名录、事务所墙面及交换业务。
- 名片制作、上传表单重设计、后台管理、认领规则或反应规则变更。
- 后端、数据库、共享契约、接口排序和分页协议变更。
- 独立名片详情路由、可分享预览链接、跨会话阅读书签。
- 列表无限滚动、强制整屏滑动、手势切卡、双指缩放和装饰性 3D 翻转。
- 全站设计 token、公共壳层重设计、原生插件和签名打包调整；仅允许本轮名片分页必要的 App 悬浮区避让。

## Acceptance Criteria
