# 名片移动浏览设计

## 状态与依据

当前方案已实现自然双列、双面同显、整体 Card 与两行移动分页，并通过 Web/App 浏览器验收。跨页预览、请求失效与返回位置逻辑保留。用户的授权及修订记录见 PRD，原生安装状态见 `research/device-delivery.md`。

需求与验收编号见 `prd.md`；初始仓库证据见 `research/current-browsing.md`。仅调整 `apps/web`，使用现有契约和 API 门面。

## 分钟级时间修订

R8 仅调整现有短时间 formatter 和 `namecardCreatedAt` 的显示字符串，使用 `formatToParts` 组合 `MM-DD HH:mm`，设置 `hourCycle: h23` 与 `Asia/Shanghai`。完整说明 formatter、ISO 数据和异常值处理不变。12px 元数据保持单行，320px 检查文字、图标和 Card 边界；单测覆盖午夜、跨年和带时区偏移的输入。选择器、接口及原生代码不改。

## 紧凑反应区修订

R7 仅修改 `NamecardReactionBar`、名片 footer 的局部留白、页私有 `NamecardReactionEmoji` 的紧凑呈现及相应测试。移动 chip 使用 16px 图形、12px 计数、紧凑内部间距，宽度至少为可用行宽的四分之一且不小于 44px；内容的自然宽度仍可扩大，避免六位数计数被裁切。加号遵守同一宽度规则。去掉移动横向 chip 间距，让反应组使用 Card 的完整内部宽度，保留日期、认领状态的内边距，并以内置焦点环避免边缘裁切。桌面恢复原样，选择器保持 20px 图形与 44px 控件。

不改变自然列算法、资产、API、计数和点击限制，不改共享 Card/Button、AppLayout 或原生插件。验证 402px 常规计数一行 4 项、320/390px 自适应换行、六位数无溢出、异步增高及桌面复原。R7/R8 已重建 iOS 26.5 模拟器 Release，竖屏流程在 `data/qa/namecard-simulator-tests/run-15.xcresult` 通过；键盘跳页后预览横竖屏再关闭的组合仍待解决，详见 `research/validation.md`。

## 本轮修复边界

用户真机反馈要求修复 App 悬浮区遮挡分页，简化时间，并统一各平台的 emoji 图形。本轮只改名片页、其私有 hook/组件、AppLayout 的名片悬浮区避让，以及相应测试与资产登记；不改原生插件、其他业务路由、API、数据库或全站 token。

名片页给分页建立可见性标记，由页私有 hook 在挂载后测量并通过 IntersectionObserver 跟踪，包含无 observer 的滚动/尺寸回退和清理。AppLayout 用限定在 App shell 的标记隐藏现有悬浮区；只改变其可见性，不卸载上传 Dialog 状态，不改变原生底栏。分页离开视口或卸载后恢复。

时间按 R8 使用 Asia/Shanghai 的 `MM-DD HH:mm`，完整年份、秒数和 ISO 数据保留在 `time.dateTime`、title 和可访问说明；不增加当前时间依赖或相对时间刷新器。反应使用页私有图形组件，从本地 `public/emoji/twemoji/` 引用固定版本 SVG，两个反应入口复用同一映射；错误时使用统一 Lucide 占位图形而非原生 emoji。46 项资产、许可和校验清单随包交付，出处登记在资产治理文件。

新增浏览器断言要覆盖 App 悬浮区与分页的实际命中，而不只检查分页内部矩形。旧版本的 903/51/5 验收不能证明新要求完成。

## 页面结构与视觉

### 窄屏列表

沿用现有 `md` 分界。窄屏采用顶部对齐、各列独立累计内容高度的双列卡片流；每个条目内部正面在上、背面在下，两个面都直接展示。达到 `md` 后保留既有多列、每条目正反并排的结构。320px 窄屏也保持两列，不能自动退回用户已否定的单列。

小红书是用户给出的图片信息流参考，不做逐像素复刻，也不引入账号社交或推荐接口。列表优先帮助用户发现和比较更多名片，缩略图不要求读清所有小字；点击任一面后在原图预览中阅读细节。

手机条目不等高，不使用固定视觉位移或额外底部占位。双列 CSS Grid 保留接口的 DOM、键盘及预览顺序，条目按原索引固定左右列。页私有 ResizeObserver 测量自然高度，各列依次累加条目高度与 12px 间距；把所有条目顶底坐标合并为有序网格边界，边界差值生成实际像素行轨道，条目使用对应起止线。轨道数随条目数增长，不随页面像素高度增长，避免 1px 隐式网格在 Firefox 大列表中触及上限并重叠。无绝对定位、变换、列优先 DOM 重排或新依赖。

首次测量在 layout effect 中执行；emoji、字体或宽度变化时重算，卸载时清理 observer 和待执行回调。桌面保留普通行网格并清除测量布局。尚未测量、不可见/无有效高度或 observer 不可用时使用普通网格回退，不能出现重叠。

浏览器验证顶部对齐、等高内容不强制错位、不同 emoji 数量下两列自然独立累计、异步增减后的重新排布、同列间距及末项/分页边界。

页面由紧凑标题、图片信息流和分页组成。每张名片是一个条目，两个图片区、提交时间、反应和认领操作保持同一内容分组；不新增介绍型首屏、悬浮操作栏或嵌套卡片。

- 两个图片区各自保留固定 3:2 舞台，使用 `object-contain`，不放大裁边。加载和失败占据同一舞台，避免后续条目跳动。
- 同一条目内正反面上下排列，两面间距约 4px；列间距优先使用现有 8px 间距，条目之间约 12px。可用轻量文字标明正面、背面，不使用列表分段控件，也不在图片内容上覆盖工具条。
- 两面都是独立图片按钮，延续各自的可访问名称。直接点击背面即可打开背面原图，不额外增加选择步骤。
- 移动条目使用现有 Card 作为可见整体容器，`bg-card`、现有细描边和 8px 外圆角把正反两图、时间、emoji 和认领状态归为一个对象。图片不再各自使用独立圆角外框，容器裁切统一外角；时间与反应区采用约 8px 内边距，保持同一背景，内容留在正常文档流。不增加嵌套 Card。
- 使用现有中性色与少量品牌强调色，不添加重复阴影、磨砂或渐变。真实名片自身的色彩承担视觉表现；桌面现有外框、圆角和操作区样式保持不变。
- 提交时间与表情互动置于两图下方的紧凑区域，不沿用大图条目的宽内边距和分层操作区。取消反应按钮的重复盒状装饰，但保留点击状态、完整计数、全部选项和 44px 目标；按实际列宽换行，不裁切。认领状态和入口依旧可见。
- 保留现有信息字段，不添加可见名片 ID、假标题、头像、作者资料、关注或收藏。

`PageShell` 继续拥有宽度与水平安全边距；本页缩短窄屏标题区和列表前的垂直留白，桌面与 App 分支保持其已有间距约束。壳层负责上传浮动入口、顶栏和底栏，页面不新增一套固定栏高度。

分页使用同一组 DOM 控件的响应式网格。手机第一行集中上一页图标按钮、页码输入/总页数、跳转和下一页图标按钮，第二行显示当前页/总量及每页数量；控制区约两行，不再散成多段。所有输入、选择与命令保持 44px 高度；桌面保留文字导航及原有设置、页码说明、跳转分组。输入支持 Enter 提交、Escape 还原当前页，未修改页码时禁用跳转；非法页码仍由既有校验反馈，不在输入中途翻页。分页和每页数量继续更新原有 URL 参数，其他筛选参数保留。验证 320px 控件边界、同排对齐、密集操作不重叠和翻页后的列表可见性；不增加弹层、固定底栏或公共分页组件。

### 原图预览

沿用 `NamecardPreview` 和现有 Dialog，保持一个弹层实例。顶部是标题、阅读位置和关闭；中间图片舞台完整显示原图；底部将上一张、正反面、下一张与缩放工具分组，窄屏分两行。

控件最小尺寸为 44px，预览使用已有四侧安全区变量。横屏减少非必要间距；图像区域使用可收缩的布局轨道，让头尾工具栏始终可见。切换图片时不重建 Dialog，避免焦点和关闭恢复逻辑反复执行。

不新增手势切卡或双指缩放。保留现有方向键语义：未放大时切面，放大后平移。上一张/下一张通过独立按钮提供；鼠标和键盘均可操作。切卡复位缩放、位移和拖动记录；切面继续遵循原有复位行为。按下图片后拖至空白区域不能关闭预览。

视觉反馈使用既有 motion token，优先直接切换或短淡入；不添加 3D 翻转，不强制动画，尊重减少动态效果设置。

## 数据流与状态

### 列表

继续由现有页面请求管理 URL 的 `page`、`size` 和列表响应。条目以 card ID 保持稳定身份；两个面始终渲染，移除原方案新增的列表可见面状态。桌面和手机只改变网格、两面排列及局部样式，不复制一套请求或业务逻辑。

缩略图仍是列表首选，原图用于预览。当前生成器等比缩小至 600 × 400 以内，不裁切；老文件可能来自未知生成流程，本任务不重做历史缩略图。缩略图失败后仅尝试一次对应原图，之后展示错误状态；图片资源身份变化时清除前一张的错误。图片加载与错误状态都占据同一舞台。

### 预览会话

打开时保存列表当前页数据、点击的索引和面、触发元素及实际滚动容器的位置。导航状态与列表状态分开，打开后的异步操作不得改写路由或列表请求参数。

预览 hook 持有当前预览页、条目索引、页面信息、请求状态和错误。只保留本次会话所需数据，不创建全局缓存、持久化书签或预取全部分页。

1. 本页存在相邻项时直接切卡。
2. 到达页边界且接口页信息表示仍有相邻页时，通过 `~/lib/api` 的 `getNamecardPage` 按当前 size 请求相邻页。向后选下一页首项，向前选上一页末项。
3. 请求期间保留当前图像，禁止重复发起导航；关闭与当前图像操作仍可用。只有成功且有可展示数据时提交新页和新索引。
4. 请求失败后保留当前项，显示错误和重试操作。空响应或总页数变化不得造成空白图像、无界递归翻页或数组越界，应提供无更多内容或重新尝试的反馈。
5. 使用会话代次或等效失效标记检查异步提交。关闭、卸载、重新打开、列表路由上下文变化后，旧响应失效；不能仅依赖取消请求，因为请求仍可能完成。
6. 每次成功切卡，面回到正面，图像变换和拖动状态复位。阅读位置由页码、size 与索引推导，不展示数据库 ID。

列表 API 使用 `NO_CLIENT_CACHE`，没有快照游标。跨页顺序按服务端当前分页响应读取，不承诺在他人新增或删除名片时保持全站快照一致性。若希望严格快照语义，应另开契约任务，本轮不变更后端。

### 返回行为

跨页预览期间保留背后列表及双面条目。关闭后对原触发元素恢复焦点，避免焦点恢复自动改变滚动位置；按记录还原实际滚动容器。触发元素已卸载时回退到可用的列表焦点位置，不调用失效节点。此规则同时用于关闭按钮、Escape 和空白区域关闭。

记录的是最初打开位置，不是最后看到的另一张名片；因此跨页阅读后返回不会突然跳到另一页。会话外的刷新、离开路由再返回不新增持久化承诺。

## 状态与可访问性

- 列表加载、空态、请求失败和重试保留现有语义。
- 原图加载中保留阅读位置与关闭入口；失败状态不会隐藏导航按钮。
- 预览中的分段控件使用一致的选中语义与明确名称；列表中两个图像按钮延续包含名片和面的可访问名称，但不增加可见 ID。
- 加载与错误使用适当状态反馈，避免每次拖动或缩放都向读屏器播报。
- Dialog 保持焦点约束、Escape 和焦点返回。仅更新图像交互区域的身份，不以 card ID 给整个 Dialog 重设 key。
- 44px 目标覆盖图片之外的切面、导航、缩放、关闭、反应与分页操作。图标通过 tooltip 和可访问名称说明含义，触屏不依赖 tooltip 完成操作。

## 兼容、风险与回滚

无需接口、数据库、路由或部署迁移。Web 与 App 共享实现；既有 App 浏览器验收不等同于原生安装。用户现追加 Android、iOS 真机局域网 Release 安装，使用现有 `app-device.js` 入口；先完成自然排布修订与验证，再构建安装，不改原生代码或持久化局域网/本地签名开关。

双列缩略图中的小字需要点开原图阅读，这是本版为提高浏览密度接受的取舍，不能用图片裁切或低于 44px 的操作按钮进一步压缩。使用常规短元数据 fixture，在 390 × 844 Web/App 首屏检查首行两张名片的正反面完整可见，并能看到下一行起始；多种反应或认领提示需要额外高度时允许正常换行。

主要交互风险是切卡后残留变换、旧请求覆盖新预览、焦点恢复引起页面跳动，以及小屏工具栏与安全区碰撞。单元测试验证状态，浏览器测试验证几何、滚动和真实图像表现；不能只靠 1px 占位图截图。

首轮 `dev:doctor` 检测到 Web 5173 和 Valkey 6379 占用。后续确认本地 API 3000 已运行并正常返回名片，复用它，通过既有 `pnpm run dev:web` 入口启动了独立 Web 5181。保留现有数据服务，不重新配置或停止它们，不提交本地环境变量或密钥。

回滚只涉及本任务的 Web 实现、测试和对应规范记录。保留原有单卡预览输入、API 和 URL 分页可降低回滚成本；不要回滚用户或其他会话的改动。
