# 社区动态移动端适配技术设计

## 设计边界

本任务只调整公开社区动态的展示与浏览体验，覆盖首页 `HomeFeed`、`ActivityHighlights`、`/events` 列表和 `/events/:eventId` 详情。Web 与 App 继续使用同一组 React 页面和 API 客户端。

不修改路由所有权、API 合约、CMS 数据、鉴权、后台编辑器、Tauri 原生标签栏或原生插件。App 与 Web 的差异仅限壳层负责的标题、返回入口、安全区和底部导航避让。

## 现有数据流

1. `HomeFeed` 分别读取首页社区动态摘要和推荐摘要，社区动态行跳转到 `/events/:eventId`。
2. `ActivityHighlights` 读取首页人工排序的推荐动态，封面可预览，文字区域跳转到详情。
3. `/events` 通过 `useEventsFeed` 读取游标分页数据，使用窗口虚拟列表、下拉刷新和无限加载。
4. `/events/:eventId` 读取公开 CMS 文章，并交给 `CommunityPostDetail` 渲染正文、活动信息、相关链接和封面预览。
5. App 壳层为 `/events/*` 提供顶部栏、返回行为、标签页归属、滚动恢复和底部留白。

数据请求、缓存、分页和错误语义保持不变。

## 首页适配

### HomeFeed

- 保留现有紧凑横向媒体行，不引入新的卡片样式。
- 标题区允许换行，避免“社区动态”和“查看全部动态”在 320px 视口争抢宽度。
- `HomeFeed` 内容容器在 App target 使用 `--app-safe-inline`，Web 继续使用现有 `px-4 sm:px-6 lg:px-8` 边距。
- “查看全部动态”保持明确的文字命令，并提供至少 44px 的触控高度。
- 动态标题、署名和联系方式继续限制行数，但补足任意长文本的断行约束。
- 加载、错误、空态和成功态保持相同内容宽度。

### ActivityHighlights

- 网格在小于 360px 时使用单列，360px 起双列，768px 起三列；因此 320×568 为单列，390px、Pixel 7 为双列，844×390 为三列，桌面保持三列。
- `ActivityHighlights` 内容容器在 App target 使用 `--app-safe-inline`，Web 保留现有三档页面边距。
- 封面保持固定宽高比，文本区保持稳定最小高度，标题最多两行并允许任意位置断行。
- 分类标签始终可见；详情入口与封面预览继续是两个独立且可访问的操作。
- 箭头不得压缩标题区域，链接触控高度不少于 44px。

## 动态列表适配

- 手机端实载行改为与现有骨架一致的紧凑双栏媒体行，基础缩略图轨道为 `6.5rem`，`sm` 起沿用较宽缩略图轨道。
- 标题限制为两行并支持任意长文本断行；摘要和联系方式在窄屏限制行数，完整内容留给详情页。
- 分类标签在触屏设备上默认可见；只有支持 hover 的精细指针设备才使用淡入效果。
- 整行继续作为一个详情链接，保留键盘焦点和按压反馈，不添加嵌套链接。
- 骨架与实载行共用相同的媒体轨道、`176px` 固定高度、间距和垂直节奏，使虚拟列表估高与实际高度一致。保留运行时测量与现有 overscan，并以延迟封面加载前后不超过 2px 的行位置和滚动位置变化作为稳定性门槛。
- 错误、空态、刷新失败和分页失败继续留在列表容器内，并保持 App 横向安全区。

## 详情适配

- `EventDetailPage` 使用共享 `PageShell` 的 `wide` 宽度和目标相关边距，不自行计算 App 安全区；通过显式 class 保留现有 `py-8 sm:py-12`，不采用 `PageShell` 的默认纵向间距。
- Web 继续显示页面内“返回社区动态”；App 依赖 `AppTopBar` 返回按钮，不重复渲染返回入口。
- 文章根节点、标题、摘要、活动信息和链接容器增加 `min-width: 0` 与任意长文本断行约束。
- 富文本容器限制所有后代的最大宽度：长链接和普通代码可断行，`pre` 与宽表格在正文容器内横向滚动，不得推动整个页面产生横向滚动。
- `CommunityPostDetail` 是公开详情与后台预览的共享组件。通用溢出修复可以留在共享组件内，但默认桌面结构和交互不变，并新增后台预览回归测试；App 返回入口和安全区类只由公开 `EventDetailPage` 传入。
- 封面图继续使用现有全屏预览组件及其四向安全区处理。
- 相关链接保持整行触控，最小高度提高到 44px；外部链接继续通过 `NavigationLink` 交给 App 系统浏览器。
- 桌面 `lg` 双栏与 sticky 侧栏保持不变。

## App 壳层兼容

- 只使用 `IS_APP_TARGET` 处理重复标题或返回入口，不通过运行时 User-Agent 分叉页面。
- 横向边距使用 `--app-safe-inline`，底部空间继续由 `AppLayout` 的 `--app-bottom-clearance` 提供。
- 不改 iOS 26 原生标签栏协商、Android Web 标签栏回退和弹层隐藏原生标签栏的现有逻辑。
- 列表仍使用窗口滚动，保持标签页回到顶部、滚动位置恢复、下拉刷新和无限加载之间的兼容关系。

## 测试设计

### 单元与组件测试

- 扩展首页动态行和首页推荐测试，覆盖长标题、窄屏布局类、触控入口与加载骨架。
- 扩展 Events 列表测试，覆盖触屏可见分类、长文本约束以及骨架和实载轨道一致性。
- 扩展详情测试，覆盖 App 返回入口差异、长 URL、`pre`、宽内容和 44px 相关链接。
- 保留分页、去重、刷新、错误和缓存行为的现有测试。

### 浏览器测试

- 新增 `tests/e2e/app-events.spec.ts`，使用稳定 API mock 覆盖 App 首页入口、列表、详情、返回、封面预览和外部链接。
- 新增非 `app-*` 命名的 `tests/e2e/events-mobile.spec.ts`，覆盖 Web Pixel 7 的首页、列表和详情流程；避免被 Web Playwright 的 `testIgnore: "app-*.spec.ts"` 排除。
- 在 `app-small`、`app-iphone`、`app-android`、`app-landscape` 和 `app-webkit` 项目中检查横向溢出、四向安全区、底部标签栏避让和触控元素边界；横屏断言直接比较内容边界与注入的左右安全区，不只检查文档宽度。
- 修复 `events.accessibility.spec.ts` 的旧标题和数据依赖，继续运行 Axe WCAG A/AA 扫描。
- 把 `activity-cover-preview.spec.ts` 的公开封面流程改为先进入详情，再打开封面预览，匹配当前产品交互。
- 在 Web 桌面和 Pixel 7 项目中覆盖首页与 Events 列表、详情；测试或验证脚本显式保存桌面和移动端截图，不依赖仅失败时截图的全局配置。

浏览器断言使用角色、可访问名称、几何边界和 `documentElement.scrollWidth <= clientWidth`，不依赖 Tailwind 类名。

## 兼容与回滚

本任务没有数据库或网络协议迁移。回滚只需恢复相关 React 组件和测试文件。若虚拟列表紧凑行在真实数据上出现测量问题，可单独恢复列表行布局，不影响首页和详情适配。

实际 Tauri 验证先运行 `pnpm --filter @imsweb/web run build:app` 和 `pnpm run app:doctor`。浏览器 App target 无法证明系统浏览器跳转或 iOS 26 原生标签栏行为；具备模拟器或设备时，分别执行 iOS 与 Android 启动烟雾测试。若本机缺少其中一端的工具链或设备，最终结果必须明确标记该端“未完成原生验证”及具体阻塞条件，不能用浏览器结果替代。
