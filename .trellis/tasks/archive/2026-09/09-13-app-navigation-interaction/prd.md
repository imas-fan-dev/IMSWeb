# App 界面导航交互优化

状态：五栏实现及适用验收已完成，用户已回复 `ok` 批准本批次提交。名片交换地图已加入底部导航；证据与平台限制见 [validation.md](validation.md)。

## 目标

重新梳理 IMSWeb App 的全局导航，让用户容易找到主要入口、理解页面归属，并在切换栏目后继续之前的浏览。页面布局只为导航可达性做必要调整。

## 背景与决策依据

用户原始需求是 "请帮我针对我们的 app 的界面导航交互进行优化"，并已同意创建任务和进入规划。用户选择重新设计导航结构，明确 "wiki内的不用改变"，随后将重点从整个页面布局纠正为 "整体的导航体验"。

已确认的产品决策：

- 用户最初批准四个一级入口，随后追加 "添加一点，在我们的导航栏里将名片交换地图加入到其中"。最终底栏为首页、社区、交换地图、资料、我的；交换地图位于社区之后，并拥有独立栏目归属。
- 用户回复 "确定"，批准切换栏目恢复上次页面和浏览位置、重选当前栏目回栏目首页、在栏目首页重选回顶。
- 最终方案展示后，用户要求在当前分支上创建 worktree 完成，并回复 "继续，子agent使用sol xhigh"。实现基于 `release/v1.1` 的 `8123bddcd80938b6ca39f5f19d17ef27d564f2ea`，按用户随后纠正，worktree 也检出 `release/v1.1`，不另开分支；目录为 `.worktrees/app-navigation-interaction`。后续子代理使用 `sol` 和 `xhigh`。

React Router 前端和 Tauri 移动壳均由 `apps/web` 所有。规划时的旧代码中，五个标签都指向固定根路径，仅尝试保存栏目根页的窗口位置。移动浏览器实测中，首页滚动后切到其他栏目再切回，位置归零；切换栏目会进入实际浏览历史。事实记录、代码位置和截图见 [代码调查](research/navigation-current-state.md)、[浏览器与决策记录](research/navigation-options.md)、[规范和历史依据](research/planning-context.md)。

## 需求

### R1 全局入口

底部一级导航按下列顺序排列。复用现有页面地址，保留已分享的内容链接。

| 一级入口 | 根路径 | 页面归属 |
| --- | --- | --- |
| 首页 | `/` | 首页、发现内容、资讯详情 |
| 社区 | `/community` | 社区动态及详情、制作人名片墙、全国支部地图 |
| 交换地图 | `/community/exchange` | 名片交换地图、事务所详情及交换区的公开子页面 |
| 资料 | `/apps` | Wiki、剧情、作品、年表及现有资料和工具入口 |
| 我的 | `/account/me` | 帐号、个人工作区、偏好设置、关于与已有帮助入口 |

交换地图作为独立底栏标签，直接打开现有地图根路径；地图内部仍沿用全屏、筛选和视角恢复，根页重选不重置视角。社区目录保留已有入口及可用性处理，底栏入口不依赖目录请求成功。旧的个人工作区路径 `/community/exchange/me` 及其子路径仍归我的。目录中的现有扩展链接须保持可达，沿用站内跳转、系统浏览器打开和 App 不可用入口过滤规则。

### R2 导航与状态连续性

| 操作 | 结果 |
| --- | --- |
| 首次点击尚未访问的栏目 | 打开栏目首页，选中对应标签 |
| 切回已访问栏目 | 恢复该栏目最近页面、地址中的分页/筛选参数和阅读位置 |
| 在子页面重选当前栏目 | 回到栏目首页顶部，此后以栏目首页作为该栏目的最近页面 |
| 在栏目首页重选当前栏目 | 保留当前地址并回顶，不新增历史记录；地图根页保留筛选和视角，不执行窗口滚动 |
| 点击子页面顶栏返回 | 返回实际浏览历史中的上一页；缺少可用 App 内历史时回所属栏目首页 |
| 直接打开已有子页面链接 | 正确选中所属栏目，并有可用的返回落点 |

状态连续性限于当前 App 使用过程。窗口滚动恢复须在延迟加载内容后仍有效，且不能与用户主动滚动争夺位置。地图继续使用已有筛选和视角恢复机制。

返回沿用当前的实际浏览历史语义，栏目切换仍进入这份历史。例如从名片墙切到我的、再切回社区续看名片墙后，顶栏返回会回到我的；回社区首页使用重选社区标签。此轮不引入每个栏目各自独立的返回栈。

栏目根页不显示顶栏返回按钮。顶栏继续说明栏目归属，页面内标题说明具体内容；地图保留全屏模式。

### R3 Wiki 边界

保留 Wiki 内部页面布局、转盘、搜索及内部导航交互。外层导航可以更新栏目归属和进入、离开 Wiki 的路径；不重写 Wiki 组件状态或内部滚动逻辑。

### R4 布局边界

只调整支持导航的顶栏、底栏、目录入口及相关空间。保留现有设计风格和安全区变量，不扩展为全站内容排版、卡片或主题重设计。地图全屏与名片墙浮动控件避让继续有效。

### R5 兼容与回归

改动限定在 App；普通 Web 保持现有导航组织。iOS 原生底栏与 Web 回退底栏提供相同的五栏与点击行为，继续使用已有弹层抑制和安全区机制。

验证覆盖 App 的 320px、小屏手机、Android 手机浏览器、横屏和 WebKit，并为 iOS UIKit 的选择、重选与弹层行为提供模拟器或设备证据。浏览器结果不能替代原生验收。名片分页、预览关闭后回到原位置、帐号各状态和页面内交互需要回归。

### R6 工作区

原工作区的发布说明脚本、邮件功能、契约、锁文件及部署配置等并行改动均留在原处，不复制进导航 worktree 或纳入本任务。导航在当前已提交基线的独立 worktree 中实现。名片移动浏览独立任务的未完成设备问题不自动归入本任务；仅修复本任务直接引入的回归。

## 验收标准

- [x] AC1 / R1：原生与 Web 回退底栏均按五栏顺序显示；交换地图可从底栏直接进入并选中，公开事务所详情归交换地图，个人工作区仍归我的；由社区可进入动态、名片墙和已开放的地图入口，由资料可进入 Wiki 与剧情，由我的可到达帐号与偏好入口；页面归属和直接链接一致，目录扩展入口未丢失。
- [x] AC2 / R2：名片墙在非第一页且已滚动时切去我的，再点社区，恢复页面、分页参数和阅读位置；深层资料页也能续看。重选当前栏目回根页顶部，再次重选回顶且不增加历史。延迟数据、连续切换、无 App 内历史的直接入口和正常返回均有交互验证。
- [x] AC3 / R3：Wiki 转盘、企划切换、搜索、内部导航及相关弹层行为保持现状；进入 Wiki 后资料标签选中，外层切换规则通过五视口回归。
- [x] AC4 / R4：每项可见改动对应导航需求，地图仍为全屏；没有无关的内容或视觉重设计。
- [x] AC5 / R5：规定视口下没有新增横向溢出、点击遮挡或浮动控件冲突；reduced motion、键盘操作、弹层抑制、名片预览返回与帐号状态通过回归。iOS UIKit 与 Android Debug 实包分别通过验收；地图成功数据流程由浏览器 fixture 验证，两端本地实包显示既有未开放状态。
- [x] AC6：`prd.md`、`design.md`、`implement.md` 和真实有效的子代理上下文清单齐备，完整方案经最终审核后才开始实现；适用静态检查、测试、构建与设备结果已记录。

- 新增或改造系统返回手势、原生权限、身份验证流程。
- 名片浏览独立任务中的既有未完成设备问题，除非本任务修改直接引入回归。
- 后端业务、数据库、生产部署、数据迁移和发布。
