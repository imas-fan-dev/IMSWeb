## 浏览器现状

通过 `pnpm --filter @imsweb/web run dev:app` 启动 `http://localhost:1420/`，在 Playwright Chromium 的 390 × 844 触屏视口检查 App target。未启动 API，因此 `/apps` 和名片等数据区域显示加载失败；本轮记录只证明全局壳层与路由交互，不证明业务数据流程或原生 UIKit 行为。

底栏的五个入口：

| 当前入口 | 目的地 |
| --- | --- |
| 首页 | `/` |
| 社区动态 | `/events` |
| 站内应用 | `/apps` |
| 地图 | `/community/exchange` |
| 帐号 | `/account/me` |

- `/community/cards` 中页面标题为 "制作人名片墙"，App 顶栏标题和底栏当前栏目均为 "站内应用"，顶栏提供 "返回"。
- `/apps` 的 App 顶栏为 "站内应用"，页面标题为 "全部入口"。
- `/account/me` 包含登录、注册、密码重置、关于及主题设置入口。
- 首页滚动至 `scrollY=600` 后，依次点击 "社区动态"、"站内应用"、"首页"，首页的 `scrollY` 为 `0`，历史索引从 `0` 增至 `3`。浏览器后退一次回到 `/apps`，索引为 `2`。这是当前行为，是否调整及目标规则还需用户确认。
- 截图等待 `[data-app-cold-start-mask]` 移除或计算透明度为 `0` 后采集；仅验证导航可点击不足以证明启动遮罩已消失，因为遮罩使用 `pointer-events-none`。

原始记录与截图位于 `research/browser/`：`app-home-current.json`、`navigation-pages-current.json`、`tab-navigation-current.json` 和五张 `app-*-current.png`。

## 已确认的四入口分组

| 一级入口 | 归属功能 |
| --- | --- |
| 首页 | 保留首页与发现入口 |
| 社区 | 社区动态、制作人名片墙、交换地图 |
| 资料 | Wiki、剧情及相关资料入口 |
| 我的 | 帐号、偏好设置与帮助 |

分组依据是用户访问目的：活动、名片与地图放在社区，资料入口单独成组。用户已接受地图不再由底栏单击直达、需要先进入社区的取舍。

Wiki 本身的转盘、搜索、布局和内部导航不变，本轮只讨论其全局入口归属。

## 已确认的栏目切换规则

各栏目记住本次 App 使用过程中的最后页面和浏览位置：从社区的名片墙切到我的，再点社区，回到刚才的名片墙及阅读位置。若用户主动再次点击当前栏目的底部标签，则回到该栏目首页；已在栏目首页时，再次点击回到顶部。

另一种行为是每次点击底部标签都打开栏目首页。它的返回规则更简单，但切换栏目会打断连续浏览，需要重新进入之前的子页面。

用户已选择保留浏览进度的规则。技术方案须明确页面地址、窗口位置与页面现有状态恢复机制的分工，不将规则扩展为保存表单草稿、弹层或所有组件状态。

## 返回与平台边界

返回沿用实际浏览历史；无可用 App 内历史时回所属栏目首页。顶栏继续显示栏目归属，具体内容由页面内标题说明。本轮不另行引入独立栏目历史栈或详情标题重设计。实现范围按用户要求限定为 App；普通 Web 保持现有导航组织。平台验证应覆盖 Web 回退底栏，并为涉及的 iOS UIKit 行为提供设备或模拟器证据，不能用浏览器替代原生验收。
