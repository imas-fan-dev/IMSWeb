# 桌面端社区与推荐双列布局

## Goal

让桌面 Web 的社区动态和向您推荐页面以双列浏览内容，并让两个页面的标题区使用同一套位置、宽度和视觉样式。

## Confirmed facts

- `apps/web/app/pages/events/index.tsx` 和 `apps/web/app/pages/recommendations/index.tsx` 都使用窗口虚拟列表、下拉刷新和无限加载。
- 两页目前的列表项均为单列。简单套用 CSS 双列网格会让虚拟器仍以每项一行计算高度，造成定位和滚动错误。
- 社区动态的桌面标题区是全宽的浅色分区，内容最大宽度为 `max-w-6xl`；推荐页标题区位于 `PageShell width="wide"` 的 `max-w-7xl` 内容容器内。两者的标题位置和背景边界不一致。
- App 目标已有独立的小屏标题和触摸刷新行为。本次请求限定桌面 Web，不应改变该分支。

## Requirements

- 社区动态和向您推荐页面在 `lg` 断点（约 `1024px`）以上，将已加载的条目按两项一行显示。
- 在移动 Web 和 App 目标中，两个列表保持单列、现有触摸刷新、无障碍语义、加载、空态、错误态和无限加载行为不变。
- 桌面双列布局必须与窗口虚拟化兼容：滚动高度、动态条目高度测量、追加加载和浏览器窗口宽度变化均正确。
- 两页桌面标题区使用相同的容器宽度、内边距、背景、底边框、标题文本层级和刷新控制对齐规则。
- 现有条目卡片的链接、可访问名称、封面、元数据和空态文案不改变。

## Acceptance Criteria

- [ ] 在 `lg` 及以上的截图或浏览器断言中，社区动态和推荐列表各自每行显示两项，且内容不重叠、不截断、不产生横向滚动。
- [ ] 在低于 `lg` 的 Web 视口及 App 目标中，两个列表仍为单列，现有刷新和加载行为可用。
- [ ] 两个桌面标题区的背景范围、内容最大宽度、左右内边距、纵向间距和标题/刷新控制对齐方式一致。
- [ ] 双列下滚动、加载下一页、刷新和改变窗口宽度后，列表项位置、顺序、无障碍列表序号及加载哨兵正确。
- [ ] 受影响的 Web 单元测试通过，并新增或更新桌面布局回归覆盖。

## Out of scope

- App 目标、移动端信息架构和移动端标题样式调整。
- 改写单个社区动态或推荐条目的内容、数据模型、接口或路由。
- 对首页、后台列表或其他内容页实施双列改版。

## Decisions

- 桌面双列从 Tailwind `lg` 断点开始。较窄的桌面和所有移动端保持单列，优先保证条目内容的可读宽度。

## Notes

- 本任务涉及两个虚拟列表实现与其回归测试，规划阶段需要提供 `design.md` 和 `implement.md`。
