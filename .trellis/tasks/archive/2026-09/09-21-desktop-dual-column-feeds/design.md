# 桌面端社区与推荐双列布局设计

## Scope and boundary

最小行为缺口是公共社区动态和推荐页在桌面仍以单列展示，且两个标题区的全宽背景、内容宽度和纵向位置不同。

本次只改变 `apps/web` 中两个公共列表页面的桌面布局、标题区组成和对应测试。保留 API 请求、分页游标、卡片内容、路由、App 目标分支和移动端单列结构。

预计修改：

- `apps/web/app/pages/events/index.tsx`：社区动态页面采用共同标题区和虚拟行渲染。
- `apps/web/app/pages/recommendations/index.tsx`：推荐页面采用共同标题区和虚拟行渲染。
- `apps/web/app/components/shared/`：新增仅承载两个公共列表共同桌面标题结构的组件；它统一全宽浅色背景、`max-w-7xl` 内容宽度、边界、标题和右侧操作的对齐，不拥有页面数据或刷新逻辑。
- `apps/web/app/lib/` 或页面私有代码：仅在搜索确认没有可复用现有实现后，放置小型 `matchMedia` 列数订阅逻辑；它只提供当前是否达到 `lg` 断点，不引入通用布局框架。
- 两页的骨架与单元测试，以及一个公共列表的桌面浏览器布局回归：证明双列、标题对齐、单列回退和无横向溢出。

不改动单条 `EventRow` / `RecommendationRow` 的信息结构、端点、合同、数据缓存或其他页面。标题共享组件只覆盖已明确的公共列表视觉规则，不抽象列表虚拟化和领域卡片。

## Layout

### Desktop public header

非 App 目标将两个页面都渲染为全宽 `border-b bg-muted/25` 标题带，内层使用 `max-w-7xl`、统一的响应式水平内边距和 `py-10 sm:py-14 lg:px-8`。标题块保留各页的 eyebrow、标题和说明，右侧保留各页现有已加载数量与刷新按钮，并继续仅在已加载条目时显示。

App 目标保留各页当前的安全区、标题大小和下拉刷新交互，不由公共桌面标题组件改变。

### Virtualized two-column rows

CSS 不能直接把绝对定位的虚拟化单项变为网格单元。列表会把连续数据条目按可见列数打包为虚拟行：

- 小于 `lg` 或 App 目标：一条记录一个虚拟行。
- `lg` 及以上的 Web：两条连续记录一个虚拟行；最后的奇数项占该行第一列。
- 每个虚拟行使用 `grid`，在双列状态使用两个等宽、可收缩的列和既有间距尺度。单条项目继续保留 `role="listitem"`、原始数据顺序、`aria-posinset` 和总项数。
- 虚拟器的 `count`、稳定 key、估算高度和 `getTotalSize()` 以虚拟行计。行容器作为唯一 `measureElement` 目标，并持续携带虚拟行 `data-index`。
- 断点变化时，`matchMedia` 订阅更新列数并请求虚拟器重新测量；列表上方偏移仍在窗口 `resize` 时同步。这样在 `lg` 两侧切换、刷新和追加分页时不会保留旧行高或错误位置。

骨架屏使用相同的 `lg` 双列和小屏单列网格，使加载态不会在首批数据到达后突然改变内容密度。

## Reuse decision

标题位置和视觉风格已在两个相同类别的公共列表中出现不一致，且本次要求它们同步变化，因此提供一个小型共享标题组件是有明确共同规则的复用。

虚拟列表的项目类型、App 生命周期处理和条目渲染不同。提取带多种回调与模式开关的通用虚拟列表会掩盖页面责任，因此只共享必要的断点订阅逻辑；每个页面在本地完成自己项目的虚拟行映射。

## Compatibility and rollback

无需迁移、接口变更或数据回填。关闭或回退此改动只需恢复两个页面的单列虚拟项映射和原有标题组合。移动 Web 与 App 分支是回归边界，必须在验证中明确覆盖。

## Risks and mitigations

- 断点切换可能使虚拟器保留过时测量值：列数变更后显式重新测量，并在浏览器测试中检查切换后的相邻行和滚动高度。
- 每个条目高度不同会使双列行高度取最高单元：测量整个行而非单个条目，并保留卡片内容的正常文档流。
- 两个标题区可能在后续独立编辑时再次偏离：样式结构由同一共享组件承载，页面只传入内容和操作。
- 虚拟化修改可能影响可访问性：保留列表、列表项、位置和总数语义，并用角色断言覆盖。
