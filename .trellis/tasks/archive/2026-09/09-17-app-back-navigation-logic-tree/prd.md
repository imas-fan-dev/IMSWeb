# 以页面逻辑树重构 App 返回导航

## 目标

App（Tauri 移动壳与移动浏览器回退构建）的返回不再回放浏览历史，而是沿着「页面逻辑树」上溯到当前页面唯一的逻辑父级。顶栏返回按钮、Android 系统返回与 iOS 边缘滑动必须给出同一个落点，让「返回」的含义只由页面归属决定，与用户此前访问过哪些页面无关。

## 背景与决策依据

用户原始需求："我发现当前的 app 条件下，整个页面的导航逻辑还是存在问题，返回按钮当前还是以 history 为基准进行导航，这样会导致我们的交互逻辑混乱，请以页面逻辑树为基准进行重新设计"。用户随后明确同意创建本任务、进入规划，并接受下列边界规则的默认设想：每个一级栏目拥有自己的逻辑树；返回不跨栏目；跨栏目跳转后返回落在目标页的逻辑父级而非来源页；原生返回手势与顶栏按钮共用同一张树。

现行实现是混合模型，这是"交互逻辑混乱"的直接来源：

- 只有「我的」子页走层级上溯（`app-tab-model.ts` 的 `appBackHierarchyTarget` 仅覆盖 `/account/me/<section>`、`/account/security`）。
- 其余页面全部落到 `hasUsableAppHistoryBack()` → `navigate(-1)`，即浏览历史回放。
- 历史不可用时回退到**所属栏目根**，而不是逻辑父级。

后果示例（现有测试明确锁定）：在社区名片墙切到「我的」再切回社区恢复名片墙后，顶栏返回会回到「我的」——返回目标由访问顺序决定，与页面归属无关。

上一条导航决策记录在 `.trellis/tasks/09-13-app-navigation-interaction/prd.md` 的 R2："返回沿用当前的实际浏览历史语义，栏目切换仍进入这份历史……此轮不引入每个栏目各自独立的返回栈"。本任务推翻该条，其余 09-13 决策（五栏结构、栏目归属、快照恢复、重选回根）全部保留。

事实记录见 [返回导航现状清单](research/app-back-affordances.md)。

## 需求

### R1 页面逻辑树

为 App 可达的每一条路由定义唯一的逻辑父级。父级用路径表示，不携带查询串与片段。树按一级栏目分根，栏目的根页面没有逻辑父级。

| 逻辑父级 | 子页面 |
| --- | --- |
| 无（栏目根） | `/`、`/community`、`/community/exchange`、`/apps`、`/account/me` |
| `/` | `/information/:contentId` |
| `/community` | `/events`、`/producer-map`、`/community/cards` |
| `/events` | `/events/:eventId` |
| `/community/cards` | `/community/cards/submissions/:id` |
| `/community/exchange` | `/community/exchange/offices/:officeSlug` |
| `/apps` | `/wiki`、`/wiki/modern`、`/works`、`/chronicle`、`/tier-list`、`/live`、`/recommendations` |
| `/wiki` | `/story`、`/story/modern` |
| `/works` | `/works/:workSlug`、`/packages/:siteSlug` |
| `/chronicle` | `/chronicle/:activityId` |
| `/account/me` | `/account/me/:section`、`/account/security`、`/account/login`、`/account/register`、`/account/password-reset`、`/about`、`/community/exchange/me` |

`/story` 与 `/story/modern` 的父级是 `/wiki`；`/wiki` 与 `/wiki/modern` 的父级是 `/apps`。`/wiki` 与 `/story` 之间的跳转由页面内已有的固定链接承担（剧情页的"企划目录"、Wiki 的"查看对应卡片"），不改变树结构。

树必须覆盖全部 App 目标路由，不得遗漏。查询串变化不产生新的逻辑节点：`/wiki?agency=X` 与 `/wiki` 是同一节点，父级都是 `/apps`。`/community/exchange/me` 归属「我的」栏目（沿用 09-13 归属），父级是 `/account/me`。

### R2 返回落点

| 当前页面 | 返回落点 |
| --- | --- |
| 有逻辑父级 | 该父级 |
| 栏目根 | 不提供返回控件 |
| 树外路由（无法匹配任何 App 路由） | 所属栏目根；无归属时回 `/`，仅作为安全兜底 |

返回落点只取决于当前地址，不取决于浏览历史、进入顺序或此前所在栏目。

### R3 三个返回入口一致

顶栏返回按钮、Android 系统返回、iOS 边缘滑动必须落到同一目标。

- 顶栏返回按钮：仅在有逻辑父级的页面显示；栏目根不显示（沿用 09-13 的既有规则，根因从"是栏目根"推广为"无逻辑父级"）。
- Android 系统返回：由应用接管的页面按树返回；栏目根保持平台默认行为。
- iOS 边缘滑动是 WKWebView 原生历史手势，无法直接改写目标。落地后若落点不是当前页的逻辑父级，必须就地纠正为该父级，纠正本身不得再次触发纠正。

### R4 保留项

- 五栏结构与栏目归属不变（`APP_TABS`、`appTabIdForPathname` 的前缀顺序与结果不变）。
- 栏目切换仍进入浏览历史并保留快照：切回已访问栏目恢复完整地址（含分页/筛选参数）与阅读位置；重选当前栏目回根页顶部且不新增历史项；地图根页保持筛选与视角，不执行窗口滚动。
- 滚动恢复、身份失效（登录/登出导致个人快照清除）、`/about` 跨身份保持阅读位置等机制不变。
- 全屏交换地图（`/community/exchange`）仍无顶栏，其内部浮层导航不变。
- 页面内已有的固定父子链接（作品详情"返回作品中心"、事务所详情"返回事务所列表"、编年史"返回编年史"、剧情页"企划目录"等）保持可达；本任务不要求它们与树完全一致，但树不得使它们失效。
- 普通 Web 构建的导航与返回不变。

### R5 兼容与回归

改动限定在 App。名片预览弹层的下标导航（`use-namecard-preview-navigation.ts` 中同名局部函数的 `navigate(-1)`）不是路由返回，不得改动。分页箭头、键盘快捷键等非返回控件不得误改。App 路由清单数量（31 条）不变，新增或删除路由必须同步 `routes-app-target.test.ts`。

### R6 已知限制

iOS 边缘滑动与 Tauri 默认 Android 返回由 WebView 会话历史驱动，无法在纯 JS 层被完全接管。栏目根页面上的原生手势仍会弹出历史（可能落在另一个栏目）。本任务通过 R3 的落地后纠正覆盖子页面场景；若仍不足，另开任务处理原生手势，不在本任务范围。

### R7 资料目录入口与标签

用户在实现阶段追加："当前的「我的资料」子页面的「剧情」入口请拿掉，将 App Wiki 修改为剧情站"。

- `coreResourceLinks` 移除指向 `/story` 的「剧情」入口。
- 指向 `/wiki` 的入口标题由「App Wiki」改为「剧情站」。
- 资料目录页面的面向用户文案不再把「Wiki」当作入口名，也不再单列「剧情」；改为以「剧情站」指代该入口。
- 资料目录的其余行为不变：核心入口在动态链接加载中与失败时仍可见，动态入口的分组、去重与扩展规则不变。

### R8 我的资料子页面去掉页面级刷新按钮

用户在同一条追加需求中要求："请拿掉所有「我的资料」下的子页面的刷新按钮"。

- `/account/me/:section`（我的资料子页面）不再渲染页面级刷新图标按钮。涉及个人档案头部、收藏夹、事务所与名片认领四个位置。
- 冲突提示里的「载入最新…」按钮、加载失败或空态里的「重新载入」按钮不属于页面级刷新控件，保留。
- 这些 section 组件同时服务独立页 `/community/exchange/me`，因此移除在两种入口下同时生效；独立页头部自己的刷新按钮不在本次范围内，保持原样。
- 地图、社区动态、生产商地图、推荐列表等其它页面的刷新按钮不在范围内。

## 范围外

- 不改五栏结构、栏目归属与底栏交互。
- 不改页面内固定链接的目标（`/about`、`/community/exchange` 等面包屑保持原样）。
- 不引入每栏目独立的返回栈，不改栏目切换进入历史的行为。
- 不改普通 Web 构建。
- 不做原生手势的接管（见 R6）。
- 不改资料目录中由 API 下发的动态入口（含其它标题为「剧情站」的链接），也不改 `/story` 路由本身。
- 不动独立页 `/community/exchange/me` 头部自己的刷新按钮。
