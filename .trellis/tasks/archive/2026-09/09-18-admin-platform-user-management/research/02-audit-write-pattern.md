# 02 audit 写入范式

调研范围：`apps/api/src/domains/admin/audit/`、`apps/api/src/ports/repositories/admin.ts`、`apps/api/src/infra/db/repositories/audit-repository.ts`、`apps/api/migrations/postgresql/0001_initial_compatibility.sql`。

**[事实]** = 源码可读；**[推断]** = 建议。

---

## 1. `writeAudit` 签名与字段

**[事实]** `apps/api/src/domains/admin/audit/write-audit.ts:5-22`：

```ts
export async function writeAudit(
    c: Context<AppEnvironment>,
    action: string,
    target: string
): Promise<void>
```

- 操作人：从 `c.get('backofficeUser')` 取 `username`、`producername`；缺失时 `username` 落 `'anonymous'`、`producername` 落 `''`（`write-audit.ts:9-10`）。
- IP：`getClientAddress(c)`（`write-audit.ts:16`；实现在 `apps/api/src/middleware/hono-context.ts:80-83`）。
- 时间：`new Date().toISOString()`（`write-audit.ts:17`）。
- 写入：`auditRepository(c).insertAuditLog({...})`（`write-audit.ts:12`）。
- **错误被吞掉**：整段包在 `try/catch`，catch 只 `console.error`，函数返回 `void`（`write-audit.ts:11-21`）。

**[事实]** `action` 与 `target` 是仅有的两个业务入参，都是自由字符串；**没有结果/成败字段**，也没有请求 ID。

---

## 2. 是否有动作枚举约束

**[事实]** **不存在**。`action` 不在 TypeScript 侧收窄，DB 侧 `logs.action TEXT` 无 CHECK 约束（`0001_initial_compatibility.sql:30-38`）。现有调用是散落的中文字符串字面量，例如：

- `'新增管理员'`（`admin-accounts/handlers/create-admin-account.ts:26`）
- `'删除管理员'`（`admin-accounts/handlers/delete-admin-account.ts:51`）
- `'新增 OAuth provider'` / `'更新 OAuth provider'` / `'删除 OAuth provider'`（`platform-auth/oauth/handlers/admin-provider-config.ts:40,87,132`）
- `'更新 SMTP 邮件配置'` / `'测试 SMTP 邮件配置'`（`platform-auth/email-settings/handlers/admin-email-settings.ts:75,97`）
- `'登录'`（走 `auditRepository.insertAuditLog` 直写，`backoffice-auth/handlers/login.ts:68-75`）

**[推断]** 新动作类型只需新增字符串常量即可，无枚举需要同步。但为了可检索，建议把新动作收敛成模块级常量（如 `ADMIN_PLATFORM_USER_ACTIONS.disable = '禁用平台用户'`），避免同义不同串。

---

## 3. 同步还是 fire-and-forget

**[事实]** **同步 await，但失败不冒泡**。`writeAudit` 内部 `await insertAuditLog`，调用方也 `await writeAudit(...)`（例：`create-admin-account.ts:26`）；插入失败只落 `console.error`，不会让业务请求失败。`login` 路径是直调 repository，同样 `try/catch` 吞错（`login.ts:76-78`）。

**[推断]** 即「审计尽力而为、不阻断业务」。若本任务要求 AR7「结果」必达，需要显式决定：沿用尽力而为，还是让写失败改变业务响应。现状不支持后者。

---

## 4. 审计记录表结构

**[事实]** 表名是 `logs`，不是 `audit_logs`。

`0001_initial_compatibility.sql:30-38`：

```sql
CREATE TABLE public.logs (
    id BIGINT GENERATED BY DEFAULT AS IDENTITY PRIMARY KEY,
    username TEXT,
    producername TEXT,
    action TEXT,
    target TEXT,
    ip TEXT,
    time TEXT
);
```

- `AuditLogInput` 一一对应：`username, producername, action, target, ip, time`（`apps/api/src/ports/repositories/admin.ts:85-90`）。
- `AuditRepository` 只有两个方法：`insertAuditLog`、`listRecentAuditLogs(limit)`（`admin.ts:91-94`）。
- 写入 SQL 见 `apps/api/src/infra/db/repositories/audit-repository.ts:11-28`；列表 SQL `SELECT * FROM logs ORDER BY id DESC LIMIT ?`（:30-36）。
- 读取端点 `GET /api/admin/logs`，handler 吞异常返回空数组（`audit/routes.ts:6-8`、`audit/handlers/list-audit-logs.ts:6-17`）；响应投影 `toAuditLogResponse` 只输出 `id/username/producername/action/target/ip/time`（`audit/response.ts:36-48`）。
- 契约 `adminAuditLogSchema` 同上六字段（`packages/contracts/src/admin.ts:134-142`）。

**[事实]** `logs` 表**没有 result/outcome 列**，`time` 是 TEXT。

## 5. 新增「平台用户处置」动作应怎么扩展

**[事实/推断]** 混合结论：

1. **[事实]** 不需要改表、不需要改枚举。直接 `await writeAudit(c, '禁用平台用户', `${accountId}`)`。
2. **[推断]** 若必须表达 AR7 的「结果」，现状只有两条路：
   - 把结果编进 `action` 或 `target` 字符串（如 `action: '触发平台用户密码重置'`, `target: 'user=<id>;result=queued'`）；**废弃 JSON 编码以免 `listRecentAuditLogs` 的 `SELECT *` 语义变复杂**。
   - 或给 `logs` 加一列 `result TEXT` 并同步改 `AuditLogInput`、`toAuditLogResponse`、`adminAuditLogSchema`。这是跨 workspace 的契约变更，成本明显更高。
3. **[事实]** `platform_accounts` 另有 `platform_security_events` 表（事件类型有枚举，见 `apps/api/src/ports/repositories/platform.ts:272-285`），专供平台侧安全事件；`deleteOAuthIdentity`、`revokeAllRefreshSessionsExcept` 等写操作**已经**在事务内写它。因此平台用户处置可以「双写」：管理端 `logs` 记录操作人审计 + 平台侧 `platform_security_events` 记录账号安全事件。
4. **[推断]** 建议：处置动作继续用 `writeAudit` 写 `logs`（满足 AR7 的「操作人」），结果编码进 target 或新增列；同时复用仓储内已有的 `PlatformSecurityEventInput` 机制写安全事件，保持平台侧事件流完整。

**[事实]** 若改 `writeAudit` 签名（加可选结果参数），全部现有调用点（≥28 处，`grep -rn "writeAudit(" apps/api/src`）都兼容可选参数，但需要一次性改 `write-audit.ts`、`AuditLogInput`、`audit-repository.ts`、`audit/response.ts`、`packages/contracts/src/admin.ts`。
