# 制作人社区动态配置

## Goal

让后台内容编辑直接管理制作人社区首页的展示，支持自定义 icon 图片，无可展示内容时入口区域为空。完成 API、后台与前台实施及验证。

## Background and confirmed scope

- 用户要求：制作人社区页面可由后台编辑修改显示，icon 位置允许使用自定义图片，没有内容时显示为空。
- 用户后续授权“开始规划实施确认”，并要求自主实施及验证；本任务按上一轮提出的入口卡片管理范围推进。
- 当前 `/community` 使用硬编码标题、简介和入口，另有名片交换服务可用性探测。Web/App 的入口不同。
- 项目已有版本化整页配置、对象存储、图片校验和上传控件，可复用这些机制。此处无须增加数据库表。

## Requirements

- R1：后台提供制作人社区管理入口，可编辑页面标题、简介与入口列表。列表支持添加、编辑、删除、调整顺序、显示/隐藏和 Web/App/全部展示范围。
- R2：每个入口配置名称、说明、跳转地址和默认图标；可上传自定义图片替换图标，也可清除图片恢复默认图标。前后台图片显示有统一尺寸，不拉伸。
- R3：op 与 editor 后台账号可管理本页；其他身份不能读取后台配置或执行写入。Cookie 写操作使用既有 CSRF 机制，写入与上传记录审计。
- R4：前台只展示配置中当前端可见的入口，不注入硬编码入口。未初始化、保存空列表、全部隐藏或全部被当前端过滤时入口区域为空。保留页面标题框架，无空态文案或假内容。
- R5：名片交换入口也归配置管理；只有配置中存在且启用的入口才检查对应功能可用性。保留功能关闭时不展示交换入口的兼容行为。
- R6：读取失败显示明确的重试操作，与有效空内容区分。后台加载失败禁止覆盖保存，保存冲突保留本地草稿并提示重新读取。
- R7：配置使用版本保护，图片上传走现有格式、大小、像素与解码校验；自定义图片引用限制在本业务已上传的公开图片。链接只允许安全站内地址和 HTTP(S)。

## Out of scope

- 动态文章、评论或用户投稿系统；现有 `/events` 内容继续由其原后台管理。
- 全站导航改造、全局视觉重设计、原生设备打包或发布上线。
- 初始化旧硬编码卡片、生产配置写入、生产数据迁移与对象清理。

## Acceptance Criteria

- [x] AC1（R1）：后台完成创建、修改、排序、隐藏、删除并保存，刷新后配置保留，公共页按保存结果显示。
- [x] AC2（R2/R7）：上传有效图片后能预览并在前台显示；清除后回到默认图标；无效图片、非法链接或不属于本业务的图片引用被拒绝。
- [x] AC3（R3）：editor 与 op 可访问和保存；匿名和其他部门被拒绝，Cookie 写入有 CSRF 与审计验证。
- [x] AC4（R4）：未初始化和保存空列表均成功返回空列表，公共页无卡片；隐藏/端过滤亦可得到空白入口区，无旧卡片回退。
- [x] AC5（R5）：交换功能关闭时不展示已配置的交换入口；删除该入口后不再探测或注入。
- [x] AC6（R6/R7）：公共请求失败可重试，后台失败不覆盖数据，旧 revision 保存返回冲突且不改写新配置。
- [x] AC7：contracts/API/Web 门禁和相关回归通过；桌面与手机浏览器核对后台及公共页，无横向溢出，并保存截图与验证记录。

逐项验收与实际限制见 [acceptance.md](./acceptance.md)，门禁和浏览器证据见 [verification.md](./verification.md)。

## Decisions and constraints

- 使用整页保存，列表顺序即展示顺序；配置缺失时入口列表为空。
- 初始标题和简介保留现有页面框架文字，但不包含旧入口列表。
- 图片成功上传后作为公开素材保留；本次不做自动删除，避免未保存草稿和并行编辑引用被误清理。上传失败依照现有补偿机制处理。
- 保留任务开始前已有 staged/unstaged/untracked 修改；不提交数据、密钥、截图等运行产物。
