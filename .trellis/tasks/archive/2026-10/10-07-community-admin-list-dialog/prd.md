# 统一制作人社区后台列表与编辑弹窗

## Goal

让运营人员在制作人社区管理页快速查看入口和调整顺序，通过弹窗维护单个入口。页面与现有资讯、剧情等后台的视觉和操作方式一致，减少浏览列表时的表单干扰。

## Background

- 用户明确要求采用「list + 编辑打开 Dialog」设计，并已授权开始本次设计。
- 当前入口编辑器把每项的完整表单直接展开，排序和删除按钮与表单混在一起：`apps/web/app/pages/admin/community/components/community-entry-editor.tsx:30`。
- 当前新增按钮在列表底部直接追加入口，所有更改通过整页「保存配置」提交：`apps/web/app/pages/admin/community/index.tsx:182`、`:244`。
- 现有后台可复用紧凑表格、面板及编辑弹窗模式：`apps/web/app/pages/admin/stories/components/story-table.tsx:28`、`apps/web/app/pages/admin/information/components/information-editor-dialog.tsx:84`。

## Requirements

### R1 后台视觉一致性

标题与简介作为基础设置，入口作为独立列表。页头、面板、按钮、字段和状态反馈使用现有后台样式；操作位置、字体层级、控件高度和留白与参考页面一致。

### R2 可扫描入口列表

列表展示顺序、图片或图标、名称与说明、展示范围、显示状态及可用性。排序、编辑和删除操作清晰可发现；隐藏项仍可管理；空列表提供后台空状态和新增入口。

### R3 新增和编辑弹窗

新增按钮位于入口列表工具区。新增和编辑共用表单弹窗，保留当前可维护字段及图片上传、预览、清除功能。新增确认后才进入列表；取消、关闭或按 Escape 保留已有列表和排序。编辑内容与原值一致时，确认只关闭弹窗。

### R4 明确的保存流程

弹窗确认将修改应用到当前页面，「保存配置」统一提交标题、简介、入口和顺序。页面明确显示未保存、处理中、同步完成、读取失败和配置冲突状态。失败保留修改；读取失败和版本冲突时继续阻止覆盖服务器配置。

### R5 图片上传与编辑归属

上传结果只能更新发起上传的编辑会话，不能写入其他入口或重新打开的弹窗。上传处理中提供明确反馈，防止重复确认和关闭引发混淆；上传失败保留已填内容，清除图片恢复所选默认图标。

### R6 窄屏和无障碍

在 320px 手机宽度下仍能读取名称和状态，完成排序、新增、编辑、删除及保存。页面与弹窗无横向溢出，长表单正文可滚动，底部操作保持可触达。弹窗标题、关闭按钮和字段具有可访问名称，键盘可完成操作，关闭后焦点返回可见触发控件。

### R7 原有业务兼容

维持 op/editor 管理权限、已有图片归属和安全链接规则、整页版本保存以及删除和重新读取的确认行为。公共社区继续完全读取服务器配置；未配置或入口为空时不注入旧入口。

## Acceptance Criteria

- [x] AC1（R1、R2）：列表和弹窗与后台参考页面使用相同的视觉语言；5 个入口不会在页面上展开成 5 套表单。
- [x] AC2（R2、R3）：新增和编辑均打开 Dialog；取消新增没有多余行，取消编辑保留原值，确认编辑只改变目标行。
- [x] AC3（R3、R4）：未更改确认不产生脏状态；弹窗确认不发送配置更新请求，只有「保存配置」发布整页修改。
- [x] AC4（R2、R4、R7）：排序、隐藏、删除、清空列表及重新读取正常；409 和读取失败仍保留修改并阻止覆盖。
- [x] AC5（R3、R5）：图片上传、预览和清除可在弹窗完成；失败可重试，过期结果不污染其他会话。
- [x] AC6（R6）：桌面和 320px 手机布局无溢出；弹窗正文可滚动且底部按钮可达，键盘操作、焦点返回和浏览器可访问性检查通过。
- [x] AC7（R7）：op/editor 的管理流程保持可用，公共页面空结果与端过滤行为的现有回归继续通过。

## Out of Scope

- 全后台逐页重设计，或更换共享字体、配色、导航和 UI 框架。
- 后端接口、存储格式、权限和数据库迁移的改动。
- 新增拖拽排序、搜索、分页或批量管理功能。
- 改写 Preview 数据，推送、部署或打包原生 App。
