# 社交分享基座与 Fudaba 名片分享：技术设计（路线 A 已确认，待实施）

## 范围与交付边界

首期分享对象只有已公开的 Fudaba 名片。完整方案仍由列表详情 Dialog、独立公开详情页和分享渠道组成，但当前实施切片只做列表详情 Dialog 与列表 emoji 折叠。独立公开详情页、Hono 动态 HTML、分享图、分享渠道和 App 原生分享继续暂缓。

当前切片复用现有名片列表响应和 reactions API，不新增或修改 wire contract。详情只展示列表已经拥有的公开字段，不能通过 owner-only 或审核接口补齐资料。本轮不渲染不可用的分享入口。

用户已批准技术路线 A：生产 Hono 为单卡 canonical URL 返回带单卡预览元数据的 Web SPA 文档，浏览器随后加载独立详情页。此次批准仅确定后续路线，不属于当前切片。

## 当前切片：列表、详情与全屏预览

- 名片卡片的正面、背面和 emoji 摘要都打开同一个详情 Dialog。移动端列表最多显示按数量降序排列的 3 个只读反应摘要；桌面端展示全部已有反应。数量相同的反应保持接口返回顺序，避免无意义重排。
- 详情仅持有从列表打开的名片会话。列表 URL 上下文变化时关闭会话；认领成功时更新选中的卡片。详情不提供跨名片按钮、位置指示或跨页读取。
- 详情展示列表已有的提交时间、企划、担当偶像、认领状态与认领人，以及正反面图片。认领入口从列表移入详情；已有的认领表单仍是独立 Dialog，提交成功后同步更新列表与当前详情状态。
- 完整 reactions API 请求和互动状态由详情拥有。列表摘要可复用同一页面级 reaction 状态缓存，但不得为列表和详情分别维护会互相覆盖的计数。点击已有反应或添加反应只在详情发生，成功后详情和列表摘要同时更新。
- 详情中的正反面图片打开现有全屏 `NamecardPreview`。全屏预览不再负责跨名片导航，只保留正反面切换、缩放、拖动、图片失败重试和关闭。关闭后回到原详情焦点，详情仍显示同一张名片。
- 关闭详情时恢复列表滚动位置和最初触发元素焦点。详情不改写列表 URL 或替换背后的列表数据；用户通过列表分页浏览其他名片。
- 移动和桌面使用同一详情组件。移动端采用适合窄视口与安全区的滚动布局，桌面端在较宽 Dialog 中并排展示正反面和参数；两者具有相同内容与操作。

## URL、公开读取与资格

- `@imsweb/contracts/paths` 定义公开页面路径构造器，建议路径为 `/community/exchange/cards/:cardId`；Web/App 路由、二维码、分享意图及 Hono 文档路由统一使用它。绝对 URL 以配置的公开站点 origin 生成，并校验为 HTTP(S)，不得使用 App scheme 或受用户输入控制的 Host。
- `GET /api/community/exchange/cards/:cardId` 返回受 contracts schema 约束的匿名公开单卡响应。仓储增加按 ID 读取的方法，复用 `apps/api/src/infra/db/repositories/fudaba-repository.ts` 的 `PUBLIC_CARD_ELIGIBILITY`，包括公开读取开关及现有系列/拥有者限制。不合格、删除或不存在统一 404；不得用 owner-only 接口回填。
- 公开投影只包含展示名、制作人、系列和偶像、简介、交换说明、主题色、可交换状态、正反面图及公开互动数据。emoji 反应按现有反应接口及权限展示；不输出 revision、审核或媒体版权字段。需要核实从现有匿名接口获取反应汇总的方式，不能把登录用户的个人反应状态写进可缓存的公开 HTML。
- 关掉 `IMS_FUDABA_PUBLIC_READ_ENABLED` 后，JSON、HTML 和分享图都返回 404；分享入口不再展示当前不可公开的内容。直接访问旧链接也不从缓存返回失效内容。

## 页面交付与社交预览

- 在 `apps/web/app/route-metadata.ts` 声明 Web/App 都可用的单卡 SPA 路由，新增路由页面与列表详情 Dialog 共用公开卡片展示组件。列表点击 Dialog 不要求改变 URL；外部链接始终进入独立页面。两处都可发起同一分享流程。
- 生产 Hono 在静态 notFound 之前注册单卡页面 GET/HEAD handler。handler 验证路径与资格、读取同一公开投影，再从已构建客户端获取 `__spa-fallback.html`，替换 head 中预留的稳定注入锚点，返回包含唯一 title、description、canonical、`og:title`、`og:description`、`og:url`、`og:image`、`og:type` 与适配的 Twitter 预览标签的 HTML。浏览器直接加载 React Router 单卡页面；抓取端无需执行 JavaScript。
- 不按 User-Agent 分流。HTML 中的动态文案和 URL 必须按 HTML 文本/属性上下文转义；图片 URL 必须是可公开抓取的 HTTP(S) 地址。构建产物的锚点缺失或重复时拒绝生成错误预览，构建测试及启动检查应及早发现。**不能使用 JSX 注释当锚点**，它不会稳定留在产物的 head 中。可选明确渲染的 anchor 元素或受测试约束的 head 转换，在实施时以产物测试验证。
- 改写后的 HTML 不继承静态模板的 ETag、Content-Length、Content-Encoding 或压缩缓存头。采用重校验缓存策略；如果缓存公开投影，必须证明下架后不会继续返回内容。Hono 渲染异常返回可恢复的服务端错误，不退回带错误预览的静态壳。
- 普通 `pnpm dev` 的 Vite 页面请求不会经过 Hono，因此开发时客户端页面可验证，爬虫 HTML 要通过打包 Web 的 Hono 集成测试或生产同构本地启动验证。Tauri 使用自己的 App 构建，直接渲染客户端详情路由，分享 URL 仍指向 Web 公共站点。

## 分享投影与渠道动作

- 分享对象引用用带类型的稳定 ID，例如 `{ kind: 'fudaba-card', id }`。API 的公开解析器产出有限的 `ShareProjection`：`title`、`description`、公开主图、主题色、canonical URL、两种图片 URL/用途；对象适配器决定公开资格与内容，渠道适配器只消费该投影。
- 共享意图/结果模型区分 `wechat`、`qq`、`xiaohongshu`、`link`，以及环境能力 `url`、`text`、`image`、`qr`、`nativeShare`。结果至少区分已交给系统、复制/下载完成、用户取消和可恢复失败；**系统面板接收不等于目标平台发布成功**。
- Web 的微信、QQ、小红书操作均为可解释的手动步骤：下载适配版式的图片、复制文案与 URL；链接入口复制 canonical URL，若浏览器提供可靠系统分享能力可按环境能力显示，但不假设网页可直接向指定平台发布。
- App 使用受控的原生系统分享面板按负载类型交接图片，或文案与 HTTPS URL；目标平台按钮共用这一层，不能假定目标应用能同时接收图片、文案和链接，也不声称直达指定应用。系统不支持、目标应用不能接收负载或图片不可用时提供保存和复制降级；取消不弹失败提示。原生命令不得接收前端任意文件路径。

## 分享图

- 同一公开分享投影驱动两套确定性布局：小红书竖版，微信/QQ 缩略图预览版。两者可生成二维码，编码的地址必须与投影 canonical URL 完全相同；主图、标题和主题色来自公开投影。
- 预览图是无需登录、可供外部抓取的独立 HTTP(S) 资源；图片 URL 应由公开分享路径构造，不依赖临时签名 URL。分享图端点每次先验证公开资格，避免下架后继续派发旧生成图。现有 `sharp` 可栅格化 SVG，但 API 容器缺少 CJK 字体；需先验证字体子集与图中文字路径方案，再选择确定性渲染方式。二维码库、字体许可、尺寸上限、生成超时和缓存策略参见 `research/native-share-and-image.md`。
- 生成失败时 Web/App 不阻断链接分享，提示图片不可用并保留复制文案/链接的操作；OG 图片失败也不得使公开详情页泄露私有数据。

## 风险、兼容与回滚

- 无既存短链、旧名片 URL 或数据迁移；新增页面、API 和图片路径不改写既有 `/community/exchange` 列表语义。
- 最大风险是 React Router 构建 HTML 与 Hono head 转换之间的契约。先实现可验证的构建锚点与原始 HTTP 预览测试，再接 UI。若生产预览异常，可关闭动态页面 handler 回退普通 SPA 仅作故障处置，但不能宣称仍满足社交预览验收条件。
- 缓存必须尊重下架、删除、公开读取关闭以及资格变化；不可对整页或图片做长时间 immutable 缓存。现有公开对象存储直链不因本设计而自动撤销，已流出的对象 URL 的更严格撤销属于现有存储策略边界，需在实施时记录。
- App 原生分享需要自有的最小权限插件和真机/模拟器验证。iOS/Android 接收端对图片加文案与链接组合支持不一，因此分享层采用可验证的图片或文案加链接两类交接，并向用户提供互补的保存/复制操作。浏览器测试只能证明能力判断、降级和 Web UI，不能证明外部平台接受了组合负载。
