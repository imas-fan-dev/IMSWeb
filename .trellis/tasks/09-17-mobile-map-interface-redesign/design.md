# 技术设计：社区交换事务所移动端地图界面重设计

> 权威来源：`apps/web/app/app.css`、`apps/web/app/pages/community/exchange/**`、
> `apps/web/src-tauri/plugins/native-glass/**`、`docs/architecture/glass-refraction-platform-strategy.md`。
> 现状证据见 `research/current-map-ui.md`。

## 1. 任务结构：单一任务 + 三轨并发

三项需求共享四个文件（`exchange-office-map.tsx`、`exchange-office-map.css`、
`community-exchange-page.tsx`、`exchange-mobile-navigation.tsx`），无法拆成可独立归档的子任务。
因此采用单任务、冻结接口、按文件所有权分轨的方式并发，这与仓库既有的
`docs/development/liquid-glass-app-shell-plan.md` 的轨道/波次做法一致。

分轨原则：**同一文件同一时刻只允许一条轨道写入。** 跨轨道需要改同一文件时，改为波次串行。

| 轨道 | 交付物 | 独占文件 |
| --- | --- | --- |
| T1 原生玻璃控件插件 | Tauri 命令、Swift 原生控件渲染、JS 客户端 | `apps/web/src-tauri/plugins/native-glass/**`、`apps/web/app/lib/native-glass-panel.ts`（新增）、其单测 |
| T2 地图控件与授权数据 | 删 `NavigationControl`、删内嵌 attribution、授权文案结构化、死样式清理 | `apps/web/app/pages/community/exchange/exchange-office-map.tsx`、`exchange-office-map.css`、`community-exchange-map-section.tsx`、`apps/web/app/app.css` |
| T3 入口与 dialog | 三处菜单入口、授权 dialog、Web 移动底栏栅格 | `apps/web/app/pages/community/exchange/community-exchange-page.tsx`、`components/exchange-mobile-navigation.tsx`、`components/exchange-map-attribution-dialog.tsx`（新增）、`components/exchange-map-attribution.ts`（新增）、相关单测 |

波次：

1. **W1 并行** — T1、T2、T3 同时启动。三者文件不重叠。T2/T3 通过下面的冻结接口对接。
2. **W2** — T4 原生接线（把原生控件挂到 T2/T3 收敛后的 DOM 结构上），随后 T5 测试与断言收敛。

T2 与 T3 之间不需要等对方完成：T3 消费的是 T2 产出的**数据类型**，而该类型定义在 T3 自己的新文件里，
T2 只是提供一个回调向下传值。接口在 W1 开始前冻结（见 §3）。

## 2. 冻结接口

以下名称与形状在 W1 开始前确定，各轨道不得单方面修改。

### 2.1 授权数据结构（W0 已落盘）

```ts
// app/pages/community/exchange/exchange-map-attribution.ts
export type ExchangeMapAttributionSegment =
  | { kind: "text"; value: string }
  | { kind: "link"; label: string; href: string }

export type ExchangeMapAttribution = {
  segments: ExchangeMapAttributionSegment[]
}
```

`parseMapAttribution(raw: unknown)` 是一个纯函数：输入 `sources[*].attribution` 字符串，
输出按原文顺序切分的段数组。该模块已由 W0 交付并通过单测
（`apps/web/tests/unit/pages/community/exchange/exchange-map-attribution.test.ts`，
`apps/web/app/pages/community/exchange/exchange-map-attribution.ts`）。T2 与 T3 **只读消费**，
不得修改其类型或函数签名。

- 解析失败或结果为空时返回 `null`，调用方退回不渲染入口，不渲染空 dialog。
- 只接受 `https://` 的 `href`；其它协议降级为纯文本段。`href` 与 `label` 都来自仓库自有的
  `apps/web/public/maps/exchange-style.json`，但解析层仍按不可信输入处理，不产生 `dangerouslySetInnerHTML`。
- 输出由 React 渲染：外链走 `components/navigation/navigation-link.tsx` 的 `NavigationLink`，
  它会把外站解析为 `system` 并渲染普通 `<a href>`；在 App 构建里则改走系统浏览器（`openSystemUrl`），
  比裸 `<a target="_blank">` 更适合 Tauri 壳。`target` / `rel` 仍然下达。
- 注意 `NavigationLink` 会把裸 origin 规范化成带尾斜杠（`https://openfreemap.org` → `https://openfreemap.org/`），
  断言 `href` 时按规范值写。

### 2.2 地图组件 → 页面的授权回调（T2 定义，T3 消费）

授权文案不必额外抓取 JSON：MapLibre 加载完样式后，`map.getStyle().sources[*].attribution`
就是权威来源。因此 `exchange-office-map.tsx` 在样式就绪后解析它，并向对外接口新增可选回调：

```ts
interface ExchangeOfficeMapProps {
  // ...既有 props
  onAttributionChange?: (value: ExchangeMapAttribution | null) => void
}

interface CommunityExchangeMapSectionProps {
  // ...既有 props
  onAttributionChange?: (value: ExchangeMapAttribution | null) => void
}
```

- section 只做透传：把 `ExchangeOfficeMap` 的回调转发给页面。
- 触发时机：样式就绪、样式内容变化（`style.load` / `styledata`）、卸载、以及加载失败时 `null`。
- 解析结果按内容相等去重，避免 `styledata` 反复上抛新对象导致页面重渲染。
- `community-exchange-page.tsx` 用 state 持有该值，并传给 `ExchangeMobileNavigation`。
- 值为 `null` 时四处入口都不渲染。这覆盖了「未解析到授权文案」和「地图配置加载失败」两种情况。

### 2.3 原生玻璃控件协议（T1 定义，T4 消费）

扩展现有插件，不新建插件目录。

Tauri 命令（`plugin:native-glass|*`，新增 `set_controls`，权限文件是
`permissions/autogenerated/commands/set_controls.toml`——生成器用下划线名，不是连字符）：

```ts
type NativeGlassFrame = { x: number; y: number; width: number; height: number }

type NativeGlassMenuItem = {
  id: string
  icon: string
  label: string
  active?: boolean
  badge?: boolean
}

type NativeGlassControl =
  | {
      id: string
      kind: "icon-button"
      icon: string
      label: string
      frame: NativeGlassFrame
      cornerRadius: number
      active?: boolean
      disabled?: boolean
    }
  | {
      id: string
      kind: "menu"
      icon: string
      label: string
      frame: NativeGlassFrame
      cornerRadius: number
      expanded: boolean
      panelWidth: number
      items: NativeGlassMenuItem[]
    }

setControls(args: { controls: NativeGlassControl[]; dark: boolean }): NativeGlassStatus
```

`frame` 使用 CSS 像素、原点在 webview 视口左上角。iOS 上 CSS 像素与 UIKit point 同尺度，
webview 铺满窗口，所以坐标平移以 webview 在宿主视图中的原点为基准。

T1 实现时选择用 `webview.scrollView.adjustedContentInset` 而非 `safeAreaInsets`：在
`viewport-fit=cover` 下后者会把安全区重复叠加一次。该选择需要设备验收重点核对，
见 `implement.md` 的 T4 验收项。

事件（原生 → Web，复用现有 `evaluateJavaScript` 派发方式）：

```js
window.dispatchEvent(new CustomEvent('ims:native-glass-control', {
  detail: { id: string, action: 'press' | 'menu-item', itemId?: string }
}))
```

JS 客户端 `apps/web/app/lib/native-glass-panel.ts`：

- `NATIVE_GLASS_CONTROL_EVENT`、`nativeGlassControlEvent(event)` 纯函数（参照 `nativeTabRoute`）。
- `syncNativeGlassControls(controls, dark)` 包装 `invoke`，返回 `NativeGlassStatus`。
- `shouldUseNativeGlassControls()`：`IS_APP_TARGET && isTauri() && isIosRuntimeIdentity(...)`。
  这是**准入判断**，不是能力判断；真正的能力判断是 `syncNativeGlassControls` 的返回。
- 不负责重试与去重；由消费 hook 决定。

### 2.4 DOM 孪生标记（T2/T3 定义，T4 消费）

需要原生化的控件加 `data-native-glass-control="<id>"`。id 取值固定为：

| id | 控件 | 归属 |
| --- | --- | --- |
| `locate` | 定位按钮 | T2 |
| `map-tools` | 菜单触发钮 | T3 |
| `map-tools`（面板） | 展开面板容器，同上 id，只为了被隐藏 | T3 |
| `refresh` | App 刷新按钮 | T3 |

`map-tools` 同时落在触发钮与其面板容器上：隐藏时两者都要消失，但**测量只能取触发钮**
（DOM 顺序里前者在前）。T4 应把面板换成独立的 `data-native-glass-twin="map-tools"`，
让隐藏规则同时覆盖两者而测量无歧义。

另外，图标的 `Lucide.xcassets` 与图标清单被 `apps/web/src-tauri/build.rs` 引入主 Asset Catalog
（`LUCIDE_CONTROL_ICONS`）——不加这一步，主应用构建不会拷入图标，原生路径会永远返回
`supported: false`。这是有意跨出插件目录的一处改动。

原生路径启用时，文档根加 `data-native-glass="controls"`；CSS 以此隐藏对应 DOM 孪生：

```css
html[data-native-glass="controls"] [data-native-glass-control] {
  display: none;
}
```

用 `display: none` 而非透明：透明会留下重复的焦点停靠点、重复的按压反馈，并且原生视图在上面会
挡住 DOM 的 tooltip。代价是原生路径下 webview 内不再有这些控件的可访问节点，可访问性由原生视图提供
（见 §5）。

## 3. 原生玻璃的分层约束（本方案的核心）

`UIVisualEffectView` + `UIGlassEffect` 只折射它**在原生图层树中下方**的内容。地图 canvas 在 WKWebView
内部，因此：

| 放置方式 | 结果 |
| --- | --- |
| 原生玻璃放在 webview **下方** | 被不透明的 canvas 遮住，不可见 |
| 原生玻璃放在 webview **上方** | 折射生效，但覆盖 DOM 控件的图标与文字 |

因此原生玻璃必须放在 webview 上方，DOM 孪生必须隐藏，**控件内容由原生绘制**：玻璃、Lucide 图标、
文案、按压反馈、激活态全部在 Swift 侧，点击经 `ims:native-glass-control` 回到 React。
这与现有 `UITabBarController` 的做法同构，也是仓库已有 `Lucide.xcassets` 随包分发模式的原因。

被否决的替代方案：

- **双 webview**（地图 webview 在下、原生玻璃居中、透明控件 webview 在上）。能同时拿到真折射与 DOM 内容，
  但需要第二个 React root 与跨 webview 状态同步，代价超过收益。
- **只把玻璃换成原生、内容留在 DOM**。z 序上不成立，玻璃会盖住内容。
- **iOS < 26 也走原生**。`UIGlassEffect` 在 iOS 26 之前不存在，退化为 `UIBlurEffect` 只会让 iOS 17–25
  拿到一个与 CSS 玻璃不一致的第三套观感。

### 3.1 几何同步

浮动控件是覆盖层，**在地图平移与缩放期间不移动**。需要重新同步的时刻是有限的：

- 挂载与卸载
- `ResizeObserver` 观察到任一孪生控件尺寸变化
- `window` 的 `resize` / `orientationchange`、`visualViewport` 的 `resize` / `scroll`
- 菜单展开/收起（面板尺寸变化）
- 状态变化（激活、徽标、禁用、加载）——只推状态，不重算几何
- 底部 tab bar 的显示/隐藏切换

不进入地图的 `move`/`moveend` 回调。这是把"原生面板 + 地图"这类方案的风险压到可控范围的关键取舍：
如果几何必须跟随地图帧同步，方案就不可交付。

同步采用整体替换（`setControls` 传全量数组）而非增量，避免 Web 与原生两侧状态发散。

### 3.2 命中测试

原生控件宿主是一个覆盖 webview 的透明容器，`hitTest` 只对落在已注册控件矩形内、且属于该控件子视图
的触摸返回命中，其余返回 `nil` 透传 webview。这与现有 `NativeTabBarOverlayView` 同构。
容器本身 `backgroundColor = .clear`、`isOpaque = false`。

### 3.3 落盘的接线结构（T4 实际交付）

T4 交付的形态比“一个 hook”多一层：页面在 `state.phase === "ready"` 的分支里套一个
`NativeGlassControlsProvider`，三个控件各自用 `useNativeGlassControl(id, spec, onEvent)` 把 DOM 孪生
注册进去。这样做的原因是：

- 三个控件分属三个组件（页面顶部刷新、地图内定位、折叠菜单），而测量、去抖、事件分发、卸载清理
  必须是同一份逻辑。放在 provider 里，组件只需交出元素引用与状态描述。
- 刷新按钮因此拆成同文件内的 `ExchangeRefreshButton`：如果 hook 放在页面组件自己身上，它就会
  从 provider 的**外部**调用，拿不到 context。
- `spec` 里只写语义（图标 id、文案、激活/禁用、菜单项），几何由孪生元素现测，所以原生尺寸永远
  跟随页面 CSS，不在 Swift 或 TS 里写第二份坐标常量。

两个实现细节值得留在文档里，否则以后会被当成 bug 重新发现：

1. **测量要先把孪生放回布局。** 原生路径生效后 `app.css` 用 `display: none` 隐藏孪生，
   `getBoundingClientRect()` 随即返回 0。provider 在一次同步读取期间把元素改成
   `display: block; visibility: hidden`，同一个任务内恢复原值，所以既测到尺寸，又不会真的画出来，
   也不会让 `ResizeObserver` 收到尺寸变化。
2. **弹层打开时推空集。** 原生控件浮在 webview 之上，Sheet 或 dialog 打开时不会被它们遮住。
   provider 订阅 `native-tab-bar-suppression` 事件，抑制期间推空数组隐藏原生控件，关闭后下一次
   同步自动恢复，不增加新的抑制通道。

菜单触发钮与它的面板是同一个控件的两部分：触发钮带 `data-native-glass-control="map-tools"`，
面板带 `data-native-glass-twin="map-tools"`，两者都被隐藏规则覆盖，测量只取触发钮，
面板仅用于读 `offsetWidth` 作为原生面板宽度。

## 4. 状态与数据流

```text
exchange-style.json ──> ExchangeOfficeMap 读取 map.getStyle().sources[*].attribution
                        └─ parseMapAttribution（W0 模块）→ onAttributionChange
                                                   │（section 只透传）
community-exchange-page（state）──────────────────┤
        │                                          │
        ├─> ExchangeMobileNavigation（App 折叠菜单 / Web 底栏）─> dialog
        ├─> 顶部标题卡（Web 768–1023px）────────────> dialog
        └─> ExchangeDiscoveryRail（Web ≥1024px）─────> dialog

NativeGlassControlsProvider（页面级）:
  useNativeGlassControl × 3 → 测量孪生 → setControls → 原生视图
  原生事件 ─> 注册时传入的 onEvent ─> 既有 React handler
```

原生事件回填到**既有** handler，不新增业务路径。菜单项的 `id` 直接映射到现有回调：
`map` → `onShowMap`、`filter` → `onOpenFilter`、`offices` → `onOpenOffices`、
`cards` → `onOpenCards`、`attribution` → 打开 dialog。

## 5. 可访问性

- 原生路径：每个控件 `isAccessibilityElement = true`、`accessibilityTraits` 为 `.button`（激活态加
  `.selected`）、`accessibilityLabel` 取 `label`、禁用时加 `.notEnabled`。菜单面板为容器视图，
  条目各自为可访问元素。
- 原生路径下 DOM 孪生为 `display: none`，webview 内不再有对应节点；这是有意让可访问树唯一。
- 非原生路径（Android / iOS < 26 / Web）：保留现有 `aria-label`、`aria-pressed`、`aria-expanded`、
  `aria-controls`、`aria-current` 语义。新增的授权入口用 `aria-haspopup="dialog"`。
- 移除 `+/-` 后 canvas 的 `aria-label` 改为手势措辞，并保留键盘可用的说明。
- `prefers-reduced-transparency: reduce` 与 `forced-colors: active` 的降级只作用于 CSS 路径；
  原生路径由系统设置自动接管。

## 6. 兼容与回退

| 运行环境 | 定位/菜单/刷新 | 玻璃 |
| --- | --- | --- |
| iOS App，iOS 26+ | 原生绘制，DOM 孪生隐藏 | `UIGlassEffect` 真折射 |
| iOS App，iOS < 26 | DOM | CSS `exchange-map-app-control` |
| Android App | DOM | WebView CSS 玻璃 |
| Web（全部宽度） | DOM | 现有 `backdrop-filter` |

回退是**自动且无残留**的：`setControls` 返回 `supported: false` 时不写 `data-native-glass="controls"`，
DOM 孪生保持可见；已写入时移除该属性。地图页是懒加载路由，离开页面即卸载原生控件。

回滚点：原生接线（T4）独立于 T1–T3。若原生路径在设备验收中不成立，去掉 `data-native-glass="controls"`
的写入即可回到纯 CSS 方案，PRD 的 R1、R2 不受影响。

## 7. 需要同步修订的文档

`docs/architecture/glass-refraction-platform-strategy.md` 当前写着「此例外只属于 App 导航层，
不改变页面内 CSS 玻璃的两层策略」。本方案把原生例外扩展到页面内浮动控件，必须修订该句并补充：
扩展的边界（仅 iOS App、iOS 26+、仅地图浮动控件）、以及 §3 的 z 序约束为何要求原生绘制内容。
该修订已随本任务落盘。

## 8. 风险

| 风险 | 处置 |
| --- | --- |
| 原生绘制内容与 CSS 版本观感不一致（字号、圆角、阴影） | 原生控件只覆盖三类控件；圆角与尺寸由 Web 侧通过 `cornerRadius` / `frame` 传入，不在 Swift 侧硬编码 |
| 几何同步漏掉某个触发时机，控件错位 | 整体替换 + `ResizeObserver` + `visualViewport` 监听；设备验收包含旋转与菜单展开两项 |
| 原生图标缺失导致 `supported: false` | 沿用现有「任一图标缺失即整体判定不支持」的语义，避免只出现部分原生化 |
| `app-map.spec.ts` 的 viewport 用例失去缩放触发器 | T5 改为手势驱动：canvas 上 `wheel` 或 `dblclick` 触发 `scrollZoom` / `doubleClickZoom`，等待 `moveend` 后断言 |
| 移除内嵌 attribution 被认定为许可违规 | R2 的验收项要求三个外链在 dialog 中完整可达；ADR 与 PRD 都记录该义务来源 |
| E2E 用 GeoJSON 源名叫 `openmaptiles` 会让地图整体失败 | `exchange-boundary-compliance.ts` 只要发现同名源就追加带 `source-layer: "boundary"` 的图层，而 MapLibre 对 GeoJSON 源上的 source-layer 报错，进而触发 `onFatalError` 并换成不可用卡片。实测用例的源改用其他 id，`openmaptiles` 本身由地图组件单测覆盖 |
| 授权入口在 ≥1024px 没有宿主 | 发现顶部工具区是 `lg:hidden`、底栏是 `md:hidden`，于是在发现侧栏表头补了第四个入口，使四个可见区间拼成无缺口全集 |

## 9. 交付顺序

T1、T2、T3 并行（W1）；T4 依赖 T2/T3 的 DOM 结构，T5 依赖全部（W2）。

T4 的设备验收需要 iOS 26 模拟器或真机。若环境不可用，T1 的 Swift 编译仍可通过 `pnpm run app:doctor`
与 `pnpm run app ios --target simulator` 的构建阶段验证，但 R3 的观感验收项必须标注为未验证，
不得以构建通过替代观感结论。
