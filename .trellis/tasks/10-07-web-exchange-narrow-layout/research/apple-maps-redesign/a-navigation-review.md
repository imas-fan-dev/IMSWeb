# App 导航宽度与大字号复核

## Result and scope

用户要求的 App 手机竖屏宽度适配已实现。R4 的 DOM／混合呈现接口检查与原生可见边界
检查通过；其保留界面切换大字号时出现工具文字裁切，独立结论为 REWORK。R5 修复该问题，
新上下文检查确认 375、402、440pt 三种机型的完整工具文字与导航对齐通过。

本页记录 R4 宽度修订和 R5 字体修复的验收范围。此前
[A final review](./a-final-review.md) 及其 R3 图库保留为历史证据。
任务继续 `in_progress`，当前变更未暂存、未提交、未发布。

## Implementation

App 手机竖屏浏览／选点表面使用当前可用宽度、公开布局边距和安全区。原生路线采用经截图
校准的 20pt 最小对称内边距，实际轮廓由原图测量验证。这是已测运行环境的布局校准，
UIKit 没有公开导航玻璃轮廓 frame。系统 `UITabBarController` 继续拥有导航。

原生搜索配 DOM 导航时接收可选实际 `navigationFrame`；DOM 搜索配原生导航时消费页面私有
布局事件。原有代次、视口、路由、可见性和失效清理校验保持。普通 Web、展开阅读、短横屏
左侧停靠及桌面侧栏继续沿用各自布局。

R5 只修改 `GlassSearchView.swift`、`exchange-more-title.swift` 和原生规范。配置式工具按钮
统一由 `UIButton.Configuration` 拥有字体，更新时请求配置刷新并使拟合尺寸失效，由工具
容器在轴向确定后完成布局。现有输入、按钮、菜单、表格、选点和查询保留。R4 宽度与 IPC
没有再次改动；内部 UIKit 裁切原因未作插桩分析。
