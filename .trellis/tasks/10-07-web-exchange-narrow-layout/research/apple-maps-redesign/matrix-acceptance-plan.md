# 当前界面截图矩阵验收

用户要求重新生成完整截图矩阵验收。继续现有任务和隔离工作树，重新运行、捕获当前产品；
R3 至 R6 原始证据不变，不把历史图片改名作为本次截图。产品源码先冻结，发现问题时保留
失败并报告，再按既有任务权限安排修复。本轮不提交、发布或安装物理设备。

## Core matrix

每个视口记录浏览、输入、结果、选点四状态。Web 桌面采用现有桌面入口和呈现，不强制底部
卡片。原生输入截图包含真实 UIKit 键盘；DOM 输入仅证明浏览器内容。核心预计 100 张：

| 呈现 | 视口 | 核心截图 |
| --- | --- | --- |
| Web / Chromium | 320×568、390×844、402×874、440×956、768×1024、900×1200、1023×768、844×390、667×375、1280×800 CSS px | 40 |
| App DOM / Chromium | 320×568、375×667、390×844、402×874、414×896、440×956、844×390、667×375、768×1024 CSS px | 36 |
| UIKit / iOS 27 | 自有 SE 3、iPhone 17、iPhone 18 Pro Max，各实际竖屏与横屏；375×667、402×874、440×956 及反转尺寸 pt | 24 |

另记录各渲染器的明暗、字体、长名称、来源／返回、错误与空结果，以及 Web 767↔768、
1023↔1024 邻界状态。按实际能力执行并逐项标记；未执行的系统设置、旧 iOS、Android
原生、VoiceOver 或 IME 不从浏览器／截图推导通过。A 原始方案与当前界面并列查看。

## Capture and acceptance

输出原始 PNG，记录像素、CSS px／pt、比例、状态、主题／字级、目标、原生能力、源码／包
绑定、fixture、命令和几何。无自动首屏滚动；先验证可见目标和实际命中，正文有意滚动另记。
检查文字、重复表面、地图净空、44pt／px 目标、48pt 侧控件及 12pt 净空；App 竖屏原生
额外检查导航可见轮廓对齐和 10 至 16pt 工具间距。桌面原有控件按其既有合同回归。

浏览器用仓库严格 dispatcher 和原超时、零重试、CI 单 worker；临时捕获配置／脚本只写
新忽略证据目录。原生复用 R6 已绑定 optimized Release，安装走 canonical App wrapper
的 `--release --skip-build`。若产品哈希或包身份不符，先报告并取得必要构建方案，不偷换
Debug／旧包。父会话拥有原生 fixture 启动／状态控制／停止；原生检查者恢复确切入口包、
设置与设备状态。浏览器服务器独立拥有，不清理未知端口／进程。

最后由新上下文检查矩阵完整性、原图和几何，逐项给出 PASS／REWORK／UNRUN，并生成
可筛选图库与原图链接。衍生缩略图仅用于导航，几何判断使用原图。新的任务注记与运行输入
分别保存，任务在全部联合验收完成前保持 `in_progress`。
