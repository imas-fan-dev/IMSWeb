# Apple Maps 参考与新版地图搜索提案

## 审阅范围

本轮研究和预览回应用户对上一版宽度、样式的否定。用户现明确批准“全部按照A类进行施工”：采用 A 四状态和浏览态五标签栏；B 与隐藏底栏对照保留为历史。适配、边界及新门禁见 [A 设计与实施合同](./a-implementation.md)。原实现、原图和旧技术验收保留。官方来源见 [资料索引](../apple-maps-redesign-sources.md)。原始观察使用 iOS 27.0 `24A434` 自有 iPhone 17 模拟器，Maps `1.0`／`2972.30.6.12.58`；不能把这次观察表述为所有最新补丁、所有设备的统一几何。

## 实际观察

原始 PNG 为 1206×2622px，层级视口为 402×874pt，比例为 3×。父会话检查了默认、输入、选点及最小搜索的完整画面。

| 状态 | 实测宽度 | 左右边距 | 说明 |
| --- | --- | --- | --- |
| 默认半屏 | 386pt，96.02% | 8pt | 搜索、账户、Places 和 Guides |
| 输入头部 | 402pt，100% | 0pt | 搜索框 315×44pt，关闭 44×44pt |
| 选点半屏 | 386pt，96.02% | 8pt | 阅读表面、标题、Share／Close、Plan |
| 选点展开 | 402pt，100% | 0pt | 实际手柄拖动进入 Expanded |
| 选点最小态 | 346pt，86.07% | 28pt | 66pt 高，保留地点摘要和关闭 |
| 搜索最小态 | 346pt，86.07% | 28pt | 66pt 高，嵌套搜索胶囊和账户入口 |

Apple 的 346pt 最小态不支持把我们的所有默认状态固定在 346／360pt。应分别评估宽度、表面高度、工具数量和展开行为。其 38／42pt 可见控件框也不是我们 44pt 最小目标的豁免；AX 框不能证明完整命中区域。

默认半屏的右侧控件是 48×104pt 的竖向组合，分别承载地图模式和定位；最小态下组合随面板下移，末端与面板相隔 16pt。没有点按这些控件。默认玻璃显露底图；输入、地点详情采用更便于阅读的浅色表面。实际材质类和精确圆角未通过公开 API 检查，不能从截图认定。

中性查询 `Tokyo Station` 的 Return 直接打开了区域地点，未出现已提交结果列表，也没有人工选择结果。输入阶段确实观察到自动补全；我们保留显式提交，不增加实时请求。原始输入图包含首次键盘说明，恢复后该说明已消失；没有执行 Continue，也不推断其消失原因。

## 新版需求草案

- 默认手机表面采用接近可用视口宽度的布局，搜索获得主要横向空间；不再用 360pt 固定上限约束手机竖屏。
- 浏览、输入、结果和选点分别确定尺寸和表面密度。浏览入口轻薄，阅读内容有稳定背景，结果保持平面列表。
- 刷新、筛选、事务所和名片在浏览／选点时直接可见；刷新独立于搜索行，仍只刷新名录。更多继续提供账号、来源和已有范围状态。
- 保留显式提交、至少两个字符、请求保护、错误恢复、IME、拖动与按钮替代、主面板互斥和原生失败回退。
- App 的完整地图与搜索许可继续进入已有来源 Dialog；本提案不重新添加 App 内独立署名浮层。Web／桌面原有署名行为保留。
- 保留品牌色、系统文本缩放、44pt 目标及 UIKit 公共材质。绘图数值不取代拟合、真实命中和系统可访问性验收。

## 两种样式方向

**A：搜索胶囊与工具分组。** 搜索是轻薄胶囊；下方一条独立工具组承载筛选、事务所和名片。刷新与定位组成右侧竖向控件。选点后搜索胶囊转为摘要，工具保留。结果使用独立阅读表面。推荐这个方向：搜索不与刷新争抢横向空间，主要业务入口仍直接可见。代价是搜索、工具、底栏三者必须一起管理遮挡和净空。

**B：搜索与工具合成宽卡。** 同样给搜索更大宽度，并把三项工具合并进一张外卡；刷新与定位仍在右侧。入口归属更集中，但默认表面更高。输入和结果沿用 A 的阅读结构。

两种方向均保留浏览态五项底栏；输入／展开时沿用导航让位和关闭恢复。另绘制了浏览态也收起底栏的导航对照，顶部“导航”打开原五项入口。该对照涉及原范围之外的常驻导航选择，尚未获得用户答复；它不是已批准的第三套实现。

## 预览数值与适配

预览使用同一 402×874pt 画布，每张独立 PNG 为 1206×2622px。A 的搜索表面为 386×68pt，工具组高 44pt；B 的宽卡为 386×142pt。搜索及更多目标均为 44pt，右侧控件目标为 48pt。选点摘要绘制为 386×74pt。它们都是本轮提案数值，尚未成为产品验收合同。

默认手机宽度提案为可用视口减左右各 8pt，不将原 360pt 上限迁回新方案。阅读表面按档位独立拟合；大档可拓宽，但仍保留原要求的可操作地图净空。真实 Apple Maps 展开可占满视口，此处需适配我们的非模态交互要求。

Web 保留网站顶栏和 1024px 桌面侧栏边界。窄屏采用相同信息层级，但安全区、CSS 视口、键盘与浏览器头部各有归属，不能把 native 点坐标当成 Web 定位常量。平板、短横屏和大字级尺寸还需补齐专项方案；本次图稿没有证明这些布局。

用户选择已确定为 A，浏览态保留五标签栏。历史技术 PASS 不扩展到新版；新的实际运行证据按实施合同收集。
