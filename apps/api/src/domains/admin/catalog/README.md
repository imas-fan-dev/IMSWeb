# 统一偶像资料管理

本域管理角色、组合／标签的企划档案、图片、类型和 Wiki 绑定。它复用现有角色、组合与 Wiki
管理分类；公开名片和 Wiki 继续使用原有路由、参数和响应契约。

- [routes.ts](routes.ts) 组合鉴权、CSRF、契约校验和命名 handler。
- [request.ts](request.ts) 是媒体 multipart 的请求校验入口；文件载体不进入共享 JSON 契约。
- [response.ts](response.ts) 把内部媒体逻辑键解析为公开 URL，不向管理浏览器暴露对象键。
- [CatalogRepository](../../../ports/repositories/catalog.ts) 负责档案版本、项目归属、互斥绑定、
  成员与导航独立性，以及共享媒体引用检查。
- [共享契约](../../../../../../packages/contracts/src/catalog.ts) 定义管理 JSON，历史名片和
  Wiki wire 仍由各自 contracts 模块拥有。

人物创建同时提交稳定身份与完整首档案；默认档案切换校验人物版本和档案归属。名称、别名、
分类、兜底及排序全部由企划档案拥有，名片目录与担当／认领展示读取默认档案，保存的担当 ID
保持不变。旧 `namecard-characters` 管理命令通过兼容写适配器维护同一份档案。
组合成员仍由 `namecard-units` 兼容命令维护。旧数据库名称是兼容视图，不是另一份人物目录。
图片写入使用不可变版本键，绑定对象的旧 Wiki 媒体入口拒绝改图。清理时核对所有资料库及独立
Wiki 图片引用，解绑复制当前展示资料并保留共享引用。

剧情工作台通过角色档案 ID 解析同企划的剧情目标：已有条目直接复用，缺失时在事务中创建绑定
条目，不复制共享图片。锁定角色与档案防止并发重复；同名独立条目要求明确关联，不按名称猜测。
已有剧情的角色关联不允许解除或改绑。人物资料更新后，名片与剧情通过各自关系读取同一来源。

角色和组合档案、图片与类型写入沿用运营权限；Wiki 绑定允许原 Wiki 编辑角色维护，不扩展到
人物主数据写权限。详情见[架构约束](../../../../../../docs/architecture/idol-catalog.md)。
